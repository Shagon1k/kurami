# Kurami UI: рабочий журнал обхода

Статус: **первый пакет UI-01…09 и QA-02 исправлен локально, ожидает выпуска**. Основание —
[согласованный план](kurami-ui-audit-plan.md). Исходная ревизия:

Владелец разрешил продолжить после проверки новых PWA-иконок.

## Среда и свидетельства

Проверки выполнялись локально в Chromium, на временных базах и синтетических
данных. Настоящие Reset, restart, repair, смена моделей и архивирование не
вызывались. Production, Access и опубликованная сборка Docs не менялись.

Добавлен `src/ui-library/testing/digest-filled.ts`: Daily с восемью письмами,
четырьмя встречами, шестью сюжетами и локальной иллюстрацией; Cinema с шестью
рейтингами, трендом, трейлерами, премьерами и новостями; Weekly с полной и
неполной неделей; Stocks с двенадцатью строками, устаревшей/недоступной котировкой
и раскрытым графиком. EN/RU используют реальные renderers, не копии их разметки.
Fixtures не обращаются к поставщикам и не используют личные данные.

В общем runner добавлены полный клиентский скрипт Digest из изолированного
сервера, четыре раздела навигации, RU Projects, выбор ширин/страниц, viewport
снимки, фрагменты длинных страниц и `layouts.json` / `audit.json`.
Для `--viewports` часы фиксированы; узкие экраны эмулируют touch-ввод.

  Палитру целиком не перекрашивать. Проверить все chart adapters после выбора.

## Пробелы и ограничения QA

### QA-01. Базовый runner ранее показывал неполные Digest страницы

Исправлено в **тестовой среде**, не в продукте: добавлены заполненные fixtures,
навигация, настоящий `briefing.js` и alias лого для лабораторных графиков.
Первоначальный runner получал injection, но не отдавал сам клиентский script.
Поэтому его старые screenshots не доказывали работу Digest charts/часов/controls.
Основные взаимодействия дополнительно проверены `test:web-browser` через compiled Digest.
После подключения скрипта выявлен ещё один пробел: static fixture server не
отдавал `/api/news/order`, и нормальный Daily показывал ошибку профиля. Добавлен
read-only ответ с исходным порядком и пустым профилем из временного сервера.
Он не имитирует персонализацию или успешную запись; все не-GET/HEAD запросы
fixture server отклоняет. Перепроверка — `dist/ui-audit/daily-order/`.

### QA-02. Контрастный анализ не учитывает градиентный фон Cinema

Автопроверка первого прохода искала ближайший непрозрачный `background-color`, а у `.cinema-winner`,
`.cinema-art` и poster fallback фон задаётся `background-image: linear-gradient`.
Она сравнивала белые цифры/подписи с фоновой бумагой, выдавая 1.00–1.16.
По источнику это ошибочная пара цветов; сами значения отчёта не доказывают дефект UI.

Исправлено: однотонные поверхности по-прежнему проверяются численно; фон с
изображением или градиентом попадает в отдельную очередь. Pixel helper временно
скрывает краску текста, загружает локальные изображения и измеряет фон под
прямоугольниками текста. Затем он восстанавливает inline styles. Низкая нижняя
граница требует ручной проверки, а не автоматически объявляется дефектом UI;
runner оставляет такой вариант неготовым.

Регрессия проверяет низкий контраст solid-фона, непрозрачный дочерний фон,
тёмный и светлый градиенты и восстановление стилей. В `after-cinema` проверены
12 сочетаний EN/RU × 320/390/1280 × light/dark; все 84 pixel bounds прошли.
Отдельный полный UI-прогон содержит 56 таких проверок без ручного остатка.
Это доказательство для измеренных состояний, **не сертификат AA всего Cinema**.

## Исключения UI guard

58 записей на старте — счётчик исходных совпадений, не число визуальных дефектов.
Первичная классификация без изменения baseline:

| Группа | Что установлено | Следующее действие |
| --- | --- | --- |
| Provider hex-matches | Четыре совпадения — HTML entities `&#160;` / `#x0*a0`, а не цвета UI | Не переписывать parsers ради счётчика |
| Retained artifact / theme metadata | Совместимость сохранённых выпусков и theme-color | Сохранить проверку безопасности и совместимости |
| Stocks/Cinema/Investment disclosures | Есть допустимые предметные карточки и expandable rankings | Не заменять их универсальным details без проверки роли |
| Docs mobile navigation | Допустимая продуктовая навигация | Проверить responsive/focus, не удалять ради нуля |
| Общие tables/disclosures/button markup | Weekly, Review и периодные ссылки частично собирают library-классы вручную | По месту перейти на renderer, сохранив DOM/client contract |
| Digest literal shapes/colours/shadow | Реальные локальные значения, в том числе media overlay/fallback | Разбирать по роли; не менять палитру Cinema вслепую |
| Library-class layout overrides | Локальные раскладки chart/teaser | Проверить существующие custom properties и потребителей |

Это source-review групп. Поэлементная визуальная проверка всех 58 совпадений
не завершена; законные исключения не считаются согласованными изменениями.
