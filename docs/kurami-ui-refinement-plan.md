# Kurami: следующая UI-полировка

Статус: **реализовано, закоммичено, отправлено в main и развёрнуто
2 октября 2026 года после подтверждения владельца. Read-only live smoke прошёл;
последующая приёмка на телефоне подтверждена владельцем 3 октября: «Все норм»**.
Основание — обсуждение и скриншоты владельца после приёмки предыдущего этапа.
Предыдущий [аудит](kurami-ui-audit-plan.md) и его
[журнал](kurami-ui-audit-findings.md) остаются закрытой историей, не новым backlog.
Общий план системы — [kurami-web-plan.md](kurami-web-plan.md).

Владелец подтвердил удаление старых доменов в Cloudflare 3 октября. Этот UI-этап не
меняет DNS/Tunnel/Access и не закрывает loopback origins. 2 октября также
согласованы компактный редактор статуса и единый max-width 1320 px для четырёх
приложений; главная Docs без боковых колонок занимает весь контейнер.

## Границы и источники

- Сохраняем стиль Kurami: тёплые поверхности, охристый акцент, общую типографику,
  небольшие тени по роли поверхности и семантические цвета статусов.
- Используем `src/ui-library/`, библиотечные renderers и theme roles.
  Повторяемые расширения вносим в библиотеку с регрессиями потребителей.
- Не копируем GitHub-подобное оформление предложенных макетов. Они показывают
  композицию, но не задают новые цвета, размеры и варианты компонентов.
- Не меняем полномочия GitHub/Run Store, правила оркестратора, расчёты финансов,
  модель авторизации и подтверждения действий. Не запускаем настоящие управляющие
  действия ради QA. Не добавляем AI-суммаризацию переписок.
- Проверяем EN/RU, light/dark, desktop и Android Chrome PWA. Содержание задач,
  источников и сохранённых выпусков не переписываем ради оформления.

Текущие контракты: [Projects DESIGN](projects-site/DESIGN.md),
[инвентарь библиотеки](ui-library-inventory.md), [header](site-header.md).
Перед реализацией сверяем их и Git: параллельная работа может изменить исходники.

Проверенные источники обсуждения:

- Projects `render.ts`, `styles.ts`, `client.js`: четыре колонки таблицы,
  fullscreen details на телефоне, отдельные Evidence/Work/Preview/Fixes/Cleanup.
- Hub `control-view.ts` и `client.js`: один заголовок диалогов, Back-template,
  Composio check отдельно от подтверждаемого apply.
- Hub `operations.ts`, `work-feed.ts`, `codex.ts`: группировка по задаче/сессии;
  обычные Codex events содержат начало/конец/прерывание, не смысловой результат.
- Метаданные Codex подтверждают служебные Guardian-подсессии. Идентификаторы,
  приватные записи и содержимое переписок не переносим в документы/fixtures.

## 1. Projects: иерархия и компактные подробности

### Список задач

- Desktop остаётся плотной таблицей. Не добавляем board/cards toggle.
- Mobile stacked rows становятся цельными компактными карточками:
  проект/номер → название → статус/стадия → проверки.
- Название — главный элемент; метаданные не конкурируют с ним.
- GitHub Project status и Suggested next сохраняют pills. Стадии Курами
  и результаты проверок — иконки и обычный цветной текст, не новые badges.
- Различаем статус задачи, текущую работу и причину внимания. «Агент исправляет»
  показываем только при соответствующем состоянии, не выводим из догадки.
- Время изменения запуска не выдаём за время синхронизации или завершения задачи.

### Подробности

- Композиция: заголовок/состояние → ресурсы → проверки с действиями → управление
  работой → опасные действия. Точные позиции редактора статуса сверяем на макете.
- Ресурсы: компактная сетка Issue/PR и Review/Discord, смысловые SVG-иконки,
  спокойные ссылки без пяти красных стрелок. Отсутствующая ссылка не оставляет
  пустую ячейку. Готовый Preview открывается возле своего состояния, без дубля.
- CI/Review/Preview — строки одного блока с общей сеткой. Причины, замечания,
  срок жизни и контекстные действия находятся возле соответствующей строки.
- Не создаём отдельные секции Preview/Fixes ради одиночных кнопок.
- Одинаковый SHA можно показать один раз; разные или неизвестные SHA не
  скрываем. Ready review не означает Passed и не скрывает замечания.
- Уже проверенный коммит не получает повторную большую disabled-кнопку и
  несколько одинаковых пояснений. Сохраняем причину недоступности там, где
  она нужна, и все доступные действия/защиты.
- Управление работой отделено от проверок. Не назначаем AI Review главным
  действием для всех задач. Главное действие зависит от подтверждённого состояния.
- Cleanup: библиотечная корзина у группы удаления, понятный крестик отмены,
  Stop для остановки. Сохранение работы и необратимое удаление визуально различимы;
  последствия и подтверждения остаются прежними.

Предложение для согласования на макете: компактное «Изменить» возле статуса
открывает редактор по запросу вместо постоянно большой Workflow-формы.
Это изменение взаимодействия, не утверждённый новый backend workflow.

Приёмка: длинная задача читается в узкой панели; один статус не повторён
несколькими блоками; все допустимые действия достижимы, ошибки и недоступность
понятны; различия SHA/свежести сохранены. Свидетельства: populated EN/RU снимки,
Projects unit/browser и UI-library/guard/export. Результат: UI и актуальный DESIGN,
соответствующие EN/RU Docs. Не входят новые метаданные задач, bulk actions,
аватары ревьюверов или декоративный процент завершённости.

## 2. Projects: интерактивные мобильные переходы

- Вправо из задачи — таблица; влево из таблицы — последняя допустимая задача.
- Панель следует за пальцем; соседняя поверхность видна под ней. После отпускания
  продолжаем с текущего положения, без стартового скачка.
- Незавершённый жест возвращается назад; уверенный завершается. Локальный порог —
  28% ширины либо 12% при скорости выше 0,5 px/ms. Ощущение и пороги ещё нужно
  подтвердить на телефоне; эмуляция не заменяет эту приёмку.
- Спокойное мягкое завершение и небольшая тень, без вращения, заметного отскока
  или имитации Tinder-карточек.
- Направление фиксируем после определения жеста; вертикальный скролл, controls,
  выделение текста и горизонтальные области не перехватываем.
- Учесть pointercancel, несколько касаний, быстрые повторные жесты, resize,
  системную навигацию и конкуренцию с краевым Back Android Chrome.
- Автообновление не заменяет DOM посреди жеста. Последняя панель доступна для
  начала движения без ожидания сети; кеш не объявляет старые данные свежими,
  а серверные проверки действий остаются обязательными.
- Сохраняем фильтры, URL/history, scroll позиции, focus, inert и блокировку фона.
  Скрытая панель не остаётся доступной клавиатуре. При подтверждении удаления
  свайпы не запускаются. Reduced motion упрощает переход.
- Клик, Back/Forward и закрытие получают согласованные переходы, без двух анимаций.

Приёмка: обе стороны следуют за пальцем; ниже порога нет перехода; отмена и
сетевая ошибка не оставляют полупанель; обычный скролл и история не сломаны.
Свидетельства: настоящие pointer sequences в browser-регрессии, slow/offline,
refresh-during-drag, keyboard/reduced motion и отдельная Android-приёмка.
Результат: клиент, motion/layout и обновлённый контракт Projects. Не входит
переписывание приложения в SPA или offline-кеширование приватных данных в worker.

## 3. Hub: Controls и единый popover-контракт

- Убрать Back из конфигурационных диалогов; закрытие через общий крестик.
- Заголовки по операции: Модели/Настройки/Composio/Перезапуск/Сброс лимитов.
  Controls остаётся названием выбора в popover.
- Размер по содержимому с ограничением по viewport. Не менять рабочие блокировки,
  CSRF, подтверждения, retry/idempotency и смысл Reset/Restart.
- Composio в меню — «Проверка Composio». Загрузка явно показывает проверку;
  check ничего не применяет. Результат — компактные строки трёх контуров с
  числом инструментов, состоянием и предупреждениями.
- Diff раскрывается у контура. Apply существует только при расхождениях,
  показывает изменения и требует подтверждения; добавить повторную проверку.
  «Синхронизировано» не означает доступность всех внешних интеграций.
- Общий контракт меню: повторный trigger/outside/Escape закрывают;
  выбор пункта закрывает меню; пустой клик внутри не закрывает.
  Для интерактивного Sync-popover внутренние поля не считаются выбором пункта.
- В коде Controls уже есть toggle; воспроизвести native light-dismiss/trigger
  порядок событий, не объявлять причину установленной до браузерной проверки.
- Focus и aria-expanded отражают реальное состояние; при outside click не
  перетягиваем focus с выбранного пользователем элемента.

Приёмка: диалоги различимы, Composio read/apply понятны, меню закрывается
одинаково мышью/touch/клавиатурой. Свидетельства: Hub browser, shared popover
fixtures и регрессии Apps/Projects Sync. Результат: UI и EN/RU owner-controls docs.
Не входят изменение контуров Composio и выполнение настоящих apply/reset/restart.

## 4. Hub: мобильный Live Activity и полезные Events

- Стрелка перехода справа сверху в отдельной колонке; заголовок до двух строк.
  Полное название доступно при раскрытии, не только в hover tooltip.
- Агент/состояние ниже, время и Events — компактная нижняя строка.
  Лог остаётся одним контейнером; первые пять и More сохраняют текущий контракт.
- Guardian-подсессии исключить из основной ленты по достоверным метаданным,
  а не title substring. Не исключать проектные AI Review или реальные ошибки.
  Служебные события привязывать к родителю только при однозначной связи.
- Классификация касается представления активности, не запуска Guardian и не
  общей статистики токенов/моделей. Не читать переписки ради summary.
- Соединять парные started/completed в один ход с длительностью только при
  наличии обеих границ одного хода. Неполные/обрезанные логи помечать честно;
  текущий usage parser хранит ограниченное число событий.
- Для задач показывать реальные CI/review/preview переходы, замечания и результат;
  для Digest — сбор/подготовку/публикацию. Повторы сворачивать с доступной хронологией.
- Сводка шаблонная, из структурированных данных, без AI-вызовов. Завершение хода
  не называть завершением задачи. Старый успех не перекрывает более свежий сбой;
  результаты не смешиваются между запусками/SHA.

Приёмка: Guardian не занимает основные пять строк; обычная сессия и проектный
review видимы; итог подтверждается исходными событиями; мобильные controls ровные.
Свидетельства: grouping/classification tests, incomplete/interrupted fixtures,
Hub browser и narrow screenshots. Результат: read projection/UI и EN/RU Hub docs.
Не входят AI-анализ кода, пересказ переписок или новые агентские задания.

## 5. Digest: Cinema и Stocks

- Cinema на телефоне: картинка над текстом новости, по аналогии с Daily stories.
  Сохраняем пропорции; без картинки нет пустой колонки. Desktop не меняем.
  Проверяем свежие и retained выпуски, длинные заголовки, fallback и lightbox.
- Карточка Stocks в Daily: title слева, «Открыть обзор» справа с вертикальным
  выравниванием. Инструмент/цена слева, изменение за сессию справа; узкий экран
  переносит блоки по правилам, не обрезает цифры. Остальные инструменты компактны.
- Сверить «Закрытие сессии» и «утренний срез» с фактическими метаданными.
  Исправлять подпись по типу данных, не менять расчёты/поставщиков.
- Expand/collapse Stocks использует общий SVG-шеврон, не текстовый V;
  состояние, доступное название и область нажатия сохранены.
- Order — подпись одного select, My order — его значение. На обычной ширине
  выровнять в один ряд, на узкой допустить перенос. Не растягивать ради пустоты.

Приёмка: нет пустой боковой колонки Cinema; карточка Stocks компактна;
шевроны согласованы, сортировка прежняя, метаданные честные.
Свидетельства: Digest header/cinema/stocks/chart regressions, populated EN/RU
mobile/desktop снимки, compiled mounted server. Результат: presentation и
соответствующие EN/RU Docs. Не входят новый график ради заполнения и переводы архива.

## Проверки, приёмка и выпуск

Базовые ширины 320/390/1280 px; реальные breakpoint-соседи проверить по коду.

Данные синтетические; снимки в игнорируемом `dist/`, не в Git.

1. Готовность: `npm run check`, `test:ui-library`, `test:ui-guard`, `test:ui-browser`,
   `ui:export` при изменении библиотеки; затронутые Hub/Projects/Digest/Docs suites
   и `test:web`, `test:web-browser`. Перед запуском сверить команды с package.json.
   Ни новых guard-исключений ради обхода QA, ни маскировки отсутствующих fixtures.
2. Общий проход: показать before/after и ограничения. Все блокирующие/существенные
   находки исправлены; отсрочка возможна только по решению владельца.
3. Согласовать scoped-коммит/пуш/выпуск отдельно. Одно прямое разрешение достаточно;
   не требовать дополнительное y после него. Проверить параллельные изменения.
4. После утверждённого выпуска — read-only live smoke и приёмка владельца в Android
   PWA. Автоматический успех, публикация и человеческая приёмка — разные записи.
5. Устойчивые контракты перенести в DESIGN/UI inventory и EN/RU Docs; этот план
   закрыть итогом и ссылками на свидетельства, не вести второй постоянный backlog.
