Cloudflare Access проверяет твою личность до передачи запроса туннелем на локальный порт. Каждый сервис слушает `127.0.0.1`. Отдельные входы Digest и Docs полагаются на политику Cloudflare; управление Hub проверяет подписанный токен, origin и CSRF-токен. Projects поддерживает проверку подписанной личности владельца через свою настройку Access. Общий шлюз дополнительно проверяет токен перед передачей запроса любому приложению. Анонимный посетитель снаружи получает вход Access вместо приватного содержимого.

## Что где доступно

| Что | Порт на сервере | Защита |
|---|---|---|
| Digest | `127.0.0.1:8787` | Cloudflare Access |
| Docs в едином входе | `127.0.0.1:8799` | Cloudflare Access через общий шлюз |
| Hub | `127.0.0.1:8800` | Cloudflare Access; его Controls дополнительно проверяют подписанный токен Access, origin и CSRF-токен |
| Projects | `127.0.0.1:8777` | Cloudflare Access; настроенная проверка токена владельца и origin для управления |
| Превью проектов, `preview-N.shagon1k.win` (N от 1 до 6) | через Caddy, `127.0.0.1:9180` | Cloudflare Access плюс ответ 404 для любого адреса без работающего превью |
| Ссылка «Open in Codex» | через Caddy | без Access: переход по точному идентификатору задачи |

## Единый вход в приложение

Общий шлюз на порту `8888` направляет запросы в Hub, Digest, Projects и Docs,
не объединяя их сервисы. Этот вход развёрнут; `/en/`
открывает Hub; `/en/digest/`, `/en/projects/` и `/en/docs/` — остальные приложения.
Русские пути начинаются с `/ru/`; `/` перенаправляет на английский.
Меню **Приложения** остаётся внутри общего входа. Hermes, Dokploy, превью
и перенаправление в Codex остаются отдельными ресурсами.

Владелец удалил четыре отдельных домена приложений. Loopback origins остаются
нужны шлюзу; они не являются новыми публичными входами.

Шлюз проверяет подписанный токен Access перед передачей приватного запроса.
Твоя политика Access только для владельца определяет, кого пускать. Шлюз проверяет
издателя, аудиторию приложения, подпись и срок действия и требует личность
пользователя приложения. Необязательный список email добавляет локальное
ограничение; служебные токены не дают доступ владельца.
Без настройки, с неверным токеном или чужим origin при записи запрос отклоняется.
Hub и Projects сохраняют собственные проверки управления. Отдельно настроенная
служебная личность читателя Docs может только читать Docs, но не панели или controls.
Удалённые домены приложений не являются запасными входами; loopback-сервисы остаются источниками общего шлюза.

Получение публичных ключей Cloudflare для проверки подписи ограничено 15 секундами.
Таймаут, ошибка сети или некорректный ответ ключей возвращают `503` с сообщением
о временной недоступности проверки входа. Обнови страницу через несколько секунд.
Неверный или отсутствующий токен по-прежнему получает `403`; без проверенной подписи
приватные данные и действия недоступны.

Одна PWA Kurami охватывает четыре приложения. Иконки лисы экспортируются прямо
из вектора в размерах 512 и 1024 пикселя, без увеличения растрового исходника.
Иконки и заставка следуют теме, выбранной в Hub: в Paper — лиса на тёплом
бежевом фоне, в Neon — лиса из неоновых трубок на тёмном. Адаптивная
иконка сохраняет лису внутри безопасной области Android; окончательную форму
определяет лаунчер. Приложение открывается на языке последней открытой страницы
(cookie `kurami-lang`), а до первой — на языке браузера. Долгое нажатие на иконку
открывает ярлыки «Дайджест», «Требует внимания» (список проблем в Hub) и «Задачи»
(Projects) на том же языке. Новые URL иконок не заставляют установленное Android-приложение
обновиться немедленно; Chrome может предложить подтвердить новую иконку в меню
приложения. Service worker получает
страницы из сети, а без связи показывает заглушку. Приватные страницы и ответы
API он не сохраняет. Единственное исключение — «Читать без сети» в новостях Daily:
после твоего согласия на этом устройстве хранится одна страница только с сюжетами,
без почты, расписания и картинок; выключение её удаляет. Развёртывание и проверка установленного приложения на телефоне
проводятся отдельно от локальных тестов маршрутизации.

Вкладка браузера и установленная PWA используют общую оболочку edge-to-edge
и безопасные отступы экрана. Прозрачность системной полосы жестов зависит от
браузера и ОС, особенно в установленной PWA на Android; страница не может
принудительно её включить. Kurami остаётся в режиме standalone, не fullscreen.
После развёртывания проверь на телефоне и вкладку, и установленное приложение:
эмуляция на компьютере проверяет раскладку, а не системные панели.

Устанавливай приложение из единого входа после авторизации. Меню Apps оставляет
Hub, Digest, Projects и Docs в этом окне, даже если сначала открыть старый адрес.
Все четыре приложения используют общие URL шрифтов. Браузер может кешировать
эти файлы оформления; приватные страницы и ответы API по-прежнему загружаются из сети.

## Превью через Caddy

Превью получают адрес вида `preview-N.shagon1k.win` по номеру слота. Caddy — отдельный сервис `kurami-preview-ingress`: он слушает `127.0.0.1:9180`, а список маршрутов собирает Project Orchestrator в файл `state/caddy/routes.caddy` по базе аренд. Маршрут есть только у превью в состоянии «работает»; на любой другой адрес Caddy отвечает 404 «no active route». Перед применением новой конфигурации Caddy проверяет её, а при сбое возвращает прежнюю. Подробнее о слотах и аренде — [Превью](@previews).

## Ссылка в приложение Codex

Discord принимает в кнопках-ссылках только HTTP(S), а Codex открывается по адресу `codex://`. Поэтому кнопка ведёт на узкий переходник в том же Caddy: он принимает только путь с точным UUID задачи и отвечает перенаправлением на `codex://threads/<uuid>`. Этот маршрут намеренно не закрыт Access: он не несёт данных, а приложение Codex проверяет твою сессию само.

## Чего в репозитории нет

Настройки Cloudflare — маршруты туннеля для `preview-1…6`, политики Access, служебный токен для автоматической проверки документации — лежат в панели Cloudflare. Репозиторий этого не проверяет и не меняет; для восстановления сервера их нужно создать вручную ([Восстановление](@recovery)). Тот факт, что анонимный запрос к адресу получает перенаправление на вход, проверяется по факту, но правила «кого пускать» из репозитория не видны. Для Hub эта зависимость самая важная: без Access области только для чтения открыты всем, кто дошёл до порта. Действия закрыты по умолчанию: без действительного токена Access для заданной команды и приложения они не выполняются.

:::code-map
- `deploy/systemd/kurami-preview-ingress.service` — сервис Caddy
- `deploy/config/Caddyfile` — настройки Caddy: локальный адрес, импорт маршрутов
- `src/orchestrator/projects/previews/ingress.ts` — сборка маршрутов по арендам
- `src/human-docs/server.ts` — сервер документации, только GET и HEAD
- `src/hub/server.ts` — сервер Hub на `127.0.0.1`
- `src/hub/access.ts` — проверка токена Access для действий Hub
:::
