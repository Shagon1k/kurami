Коннектор — это внешний набор инструментов, через который агент или скрипт Kurami обращается к Gmail, Calendar, YouTube и другим сервисам. Kurami делит доступ не по задачам, а по полномочиям: есть три уровня, и каждая операция обязана выбрать ровно один. Так фоновая работа физически не может оказаться в канале, где разрешено писать.

:::glance
- Уровни: `composio-read` (только чтение), `composio-automation` (одно разрешённое действие), `composio` (широкий, для тебя)
- Два списка, которые должны совпасть: политика сессии в Composio и `tools.include` в Hermes
- Кто вызывает: опросы и Daily — `read`; кнопка «Прочитать и архивировать» — `automation`; ты в чате — `composio`
- Проверка расхождения: команда `/kurami composio-check` в Discord
- Четвёртый коннектор: Telegram MCP — источник новостей Daily
- Секреты: отдельные каталоги `.env` с правами 0600, в Git их нет
:::

## Три уровня

```diagram
kind: graph
title: Три уровня доступа Composio
desc: Фоновое чтение идёт через сессию read с семью инструментами чтения. Единственное автоматическое действие, архивирование писем, идёт через сессию automation с одним инструментом. Широкая сессия нужна только для работы по твоей просьбе и требует подтверждения записей.
node ingest "Опросы и Daily" "фоновое чтение" at 0,0
node mail "Кнопка в Digest" "прочитать и архивировать" at 1,0
node you "Ты в чате" owner at 2,0
node read "composio-read" "7 инструментов чтения" at 0,1
node auto "composio-automation" "1 инструмент записи" at 1,1
node broad "composio" "широкий" at 2,1
node hermes "Hermes" "второй список, trust" at 1,2
node composio "Composio" "сессии и аккаунты" external at 1,3
group kurami "Kurami" ingest mail
edge ingest -> read
edge mail -> auto
edge you -> broad
edge read -> hermes
edge auto -> hermes
edge broad -> hermes
edge hermes -> composio "MCP"
```

| Уровень | Кто вызывает | Побочные эффекты | Доверие Hermes |
|---|---|---|---|
| `composio-read` | опросы, Daily, пробные проверки | нет: только инструменты с пометкой `readOnlyHint` | `untrusted` |
| `composio-automation` | кнопка чтения и архивации писем из Digest | только `GMAIL_BATCH_MODIFY_MESSAGES` | `full` |
| `composio` | ты, в интерактивной работе | широкие; запись требует подтверждения | `untrusted` |

Инструменты `composio-read`: `GMAIL_FETCH_EMAILS`, `GMAIL_FETCH_MESSAGE_BY_MESSAGE_ID`, `GOOGLECALENDAR_EVENTS_LIST` и четыре инструмента YouTube. В широкой сессии Hermes видит лишь три служебных инструмента: поиск, схемы и множественное выполнение.

## Два списка должны совпасть

Доступ ограничен дважды, и оба ограничения независимы. Первое — политика сессии, которую читает Composio: какие инструменты включены, какие теги запрещены (`destructiveHint` запрещён везде), выключены ли управление подключениями и workbench. Второе — список `tools.include` в конфигурации Hermes, который записывает команда `install-hermes-*`. Если кто-то добавит инструмент записи в одну из сторон, второй список его не пропустит.

Доверие `full` у сессии automation безопасно только потому, что список состоит из одного точного инструмента: решение «разрешить» принято один раз при проверке списка, а не при каждом вызове. Новое автоматическое действие — это изменение YAML-файла политики, списка Hermes, документа о полномочиях и тестов, и всё это проходит ревью.

## Правила аргументов проверяет код

Инструмент `GMAIL_BATCH_MODIFY_MESSAGES` умеет и добавлять, и убирать любые метки, а размещённый MCP Composio не применяет ограничения аргументов. Поэтому узкое правило держит сам код workflow, а не Composio. Перед вызовом он обязан убедиться, что:

- `userId` равен `me`, а идентификаторов писем от 1 до 1000;
- `addLabelIds` пустой или не задан;
- `removeLabelIds` — непустое подмножество `INBOX` и `UNREAD`;
- идентификаторы взяты из сохранённого результата чтения, а не из текста письма или ответа модели.

Так кнопка «Прочитать и архивировать» убирает метки `UNREAD` и `INBOX`, но не может удалить письмо, отправить ответ или поставить метку. Если когда-нибудь понадобится проверка на стороне инструмента, нужен локальный адаптер с фиксированной операцией.

## Сверка: `/kurami composio-check`

Команда показывает все три уровня сразу и сверяет каждую живую сессию с желаемым состоянием из `deploy/config/connectors/`. Ты выбираешь уровень в списке «Choose capability contour…». Кнопка «Apply <уровень> changes» появляется только для выбранного уровня, у которого есть расхождение, и привязана к версии сессии, списку инструментов и показанной разнице: если что-то поменялось между показом и нажатием, она откажется. Создание сессии и установка конфигурации в Hermes — операции развёртывания через CLI `bin/kurami-composio-session`, из Discord они недоступны.

## Telegram как четвёртый коннектор

Новости Digest читаются из Telegram-каналов через твой аккаунт. Для этого Hermes подключает отдельный MCP-сервер `telegram` с 15 инструментами и полным доверием; обёртка Kurami добавляет инструменты сбора и завершения Daily. Дело не в широте доступа, а в том, что у этого сервера нет уровней: он читает указанные каналы, скачивает картинки и помечает прочитанным. Прочитанным канал становится только после публикации выпуска и только до сохранённой границы: если публикация провалилась, ничего не отмечается.

::::example Кнопка «Прочитать и архивировать» в Digest (данные выдуманы)
:::steps
- **Опрос Digest** — в 07:37 через `composio-read` получает 12 непрочитанных писем и записывает их идентификаторы в базу.
- **Ты** — выбираешь на странице три письма и нажимаешь кнопку архивации.
- **Код Digest** — берёт идентификаторы из базы и собирает вызов: `userId=me`, `removeLabelIds=[INBOX, UNREAD]`, `addLabelIds` пуст.
- **Код Digest** — проверяет правила выше. Если в запросе есть что-то ещё, вызов не выполняется.
- **Hermes** — передаёт вызов `composio-automation`, где разрешён один инструмент, и Composio убирает две метки у трёх писем.
- **Digest** — сохраняет квитанцию действия и обновляет страницу.
:::

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Сессия разошлась с YAML | `/kurami composio-check` показывает разницу | проверить и нажать Apply |
| Инструмента нет в списке Hermes | вызов отклоняется | добавить через ревью; фоновый код на широкую сессию не переключится |
| Аргументы вызова не по правилам | workflow не вызывает инструмент | ничего; ошибка остаётся в журнале |
| Composio недоступен | Digest помечает блок устаревшим и продолжает | подождать или проверить сессию |

:::guarantees
- Фоновая работа не использует широкую сессию ни при каком сбое.
- В `composio-read` нет ни одного инструмента записи.
- Автоматически можно только убирать метки `INBOX` и `UNREAD`.
- Идентификаторы писем берутся из сохранённого чтения, а не из текста.
- Ключи, адреса сессий и идентификаторы аккаунтов не хранятся в Git.
:::
