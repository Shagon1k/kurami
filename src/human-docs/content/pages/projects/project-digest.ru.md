Projects Digest держит для каждого проекта одну карточку в закрытом канале Digest. Она отвечает на вопрос «что взять в работу следующим». Карточка только советует: она не переносит задачи, не ставит приоритеты сама и не запускает Codex. Перенос в In progress остаётся твоим решением.

## Что предлагает карточка

Блок **Suggested next** называет одну задачу из Backlog и одной строкой объясняет выбор: «Owner priority P1 · Effort M · Waiting 9 days · Ready to start». Выбор идёт по фиксированным правилам, без ИИ. Сначала смотрится приоритет, который поставил ты: чем он выше, тем раньше задача. Среди задач с одним приоритетом выигрывает та, у которой лучше сумма двух оценок: малый Effort и возраст (ожидание считается до 30 дней). При полном равенстве берётся меньший номер задачи.

В выбор попадает только готовая к запуску задача: она открыта, стоит в Backlog, у неё есть описание, её не блокирует открытая задача и по ней нет активного запуска. Если таких нет, карточка пишет «No eligible backlog issue right now.» Задачи с меткой `no-auto` остаются в общих счётчиках доски, но не участвуют в предложениях и AI-оценке Priority/Effort.

Ниже идёт таблица счётчиков из четырёх строк: Open и Ready, Backlog и Active, Review и Blocked, Deferred и Done. **Open** — открытые задачи, кроме Done и Deferred. **Ready** — задачи, которые можно взять прямо сейчас.

Карточка обновляется раз в сутки в 06:45 UTC и в течение минуты после переноса карточки на доске или записи метаданных. Внизу указано, когда предложение появилось и когда факты проверялись в последний раз.

## Предложения метаданных

ИИ умеет заполнять только пустые поля. Если у задачи в Backlog не заполнен Priority или Effort, Kurami раз в сутки собирает для проекта пакет таких задач и просит Codex в режиме «только чтение» предложить значения: Priority — P1, P2 или P3, Effort — от XS до XL. P0 ИИ предложить не может. Он не выводит зависимости и пропускает задачу, если данных мало: предложения тогда нет.

За сутки оценивается не больше 12 задач на проект. Число меняется в `/kurami settings` (0 отключает ИИ).

Готовый пакет ждёт тебя на карточке: «Ready · N pending». Решаешь ты, кнопками.

| Кнопка | Что делает |
|---|---|
| **Review proposals** | Открывает список только для тебя: у каждого предложения задача, поле, значение и причина. Здесь можно исключить лишнее или вернуть исключённое и нажать Accept remaining |
| **Accept batch** | Принимает все оставшиеся предложения. В GitHub при этом ничего не пишется |
| **Discuss batch** | Открывает тред, где можно обсудить пакет. Обсуждение ничего не меняет |
| **Skip batch** | Отклоняет пакет целиком |
| **Review approved batch** / **Review sync result** | Показывает принятый пакет или итог записи |
| **Retry sync** | Появляется после двух неудачных попыток записи и запускает их заново |

После **Accept batch** карточка показывает «Approved», а в течение минуты защищённая синхронизация записывает значения в GitHub Project. Для каждого поля она заново читает текущее значение. Пустое поле или поле со значением, которое ранее записал сам Kurami, обновляется. Если ты успел поставить значение вручную, оно остаётся, а предложение помечается как конфликт. Итог виден на карточке: «Applied», либо «Partially applied» с числом сохранённых значений.

Как устроены снимок фактов, формула и пакеты, описывает страница [Как Projects Digest выбирает задачу](@planning-internals).

## Что остаётся за тобой

Значения, которые ты поставил сам, включая P0, Kurami не переписывает. Задачи он не переносит и не создаёт. Запуск начинается только с твоего переноса карточки на доске — см. [Статусы доски](@board-statuses).
