Очистка — это шаг, который удаляет рабочую копию и локальную ветку запуска только тогда, когда Kurami может показать, что ничего ценного не пропадёт.

:::glance
- Что делает: останавливает Codex, убирает превью, проверяет слияние и удаляет копию и ветку; при отмене сохраняет всё, что нельзя восстановить
- Кто запускает: ты — переносом карточки в Done, Backlog или Deferred либо кнопкой Cancel run; дальше контроллер раз в минуту
- Где работает: скрипты завершения и отмены, которые вызывает контроллер
- Состояние: `runs.state` (`stopping` → `archived`, `cancelled` или `needs_attention`), `stop_reason` (`completed` или `cancelled`), `resource_state`
- Итог: `archived` — PR слит, `cancelled` — запуск отменён; при сомнении `needs_attention` и сохранённая работа
- За тобой: слияние PR и подтверждение удаления сохранённой работы
:::

## Два намерения

Kurami различает два намерения и записывает их в `stop_reason`: `completed` — ты закончил работу, `cancelled` — ты её отбросил. Различие нужно потому, что удалять после завершения безопасно, если коммиты уже в основной ветке, а после отмены можно потерять чужую работу.

| Что ты делаешь | Что записывает Kurami | Чем кончается |
|---|---|---|
| Переносишь карточку в Done | `stopping`, `stop_reason=completed` | `archived`, когда слияние доказано |
| Переносишь из In progress или Human Review в Backlog или Deferred | `stopping`, `stop_reason=cancelled` | `cancelled` или `needs_attention` с сохранённой работой |
| Нажимаешь **Cancel run** | то же; другие ожидающие запросы отклоняются | то же |

Отмена сильнее остальных сигналов: если отмена уже запрошена, перенос в Done или Human Review её не отменяет. Задача с меткой `preview-required` при переносе в Done ждёт, пока ты отметишь превью текущего коммита как просмотренное; только после этого запуск переходит в `stopping`. Как это выглядит в Discord — в [Статусах доски](@board-statuses), [Превью](@previews) и [Управлении из Discord](@owner-controls).

## Остановка

Сначала контроллер снимает то, что ещё работает. Если у запуска есть tmux-сессия Codex, он нажимает Escape, вводит `/exit` и через пять секунд убивает сессию. Хвост терминала уходит в `logs/session-completions/` или `logs/session-cancellations/`. Затем контроллер убирает превью запуска. Копию нельзя трогать, пока в ней работает процесс, поэтому очистка ждёт обоих шагов.

## Завершение и подтверждение слияния

Kurami удаляет копию после Done только тогда, когда видит, что коммит запуска попал в основную ветку. Причина простая: удалённая ветка с неслитой работой не восстанавливается.

Скрипт очистки выполняет `git fetch --prune origin main` и проверяет одно из двух условий. Либо HEAD копии является предком `origin/main` — так выглядят обычное слияние и fast-forward. Либо `gh pr list --state merged` находит слитый PR этой ветки, у которого `headRefOid` равен HEAD копии — так выглядят squash и rebase. Только точный совпавший коммит считается доказательством: PR с другим коммитом ничего не значит.

Если доказательство есть, скрипт выполняет `git worktree remove` без `--force` и `git branch -D`, удаляет каталог попытки и переводит запуск в `archived`. Несохранённые файлы блокируют очистку ещё до удаления, а `worktree remove` без `--force` — вторая защита. Если доказательства нет, скрипт ничего не удаляет: запуск переходит в `needs_attention` с причиной `completion_waiting_for_merge`, а карточка пишет «Done has no verified merge. Work is preserved; merge the pull request or cancel the run.». Проверка слияния повторяется каждую минуту: как только ты сольёшь PR, запуск завершится сам. Если PR сливать не нужно, нажми **Cancel run** — дальше идёт обычная отмена с защитой работы.

## Отмена и защищённая очистка

При отмене очистка строже, чем при завершении: отменённый запуск не становится `archived`, даже если его ветка случайно оказалась слитой. Скрипт удаляет копию сам, только если она чистая, а ветка не ушла дальше `base_sha`. Тогда запуск получает `cancelled`, а контроллер переносит карточку в Backlog.

Если в копии есть несохранённые файлы или коммиты сверх базы без доказательства слияния, скрипт отказывается. Запуск переходит в `needs_attention` (`worktree_release_blocked`), а карточка показывает «Cancelled — local work preserved» или, если есть PR, «Cancelled — published work preserved». Всё остаётся на месте, пока ты не решишь.

## Сохранённая работа и подтверждение удаления

Сохранённую работу удаляешь только ты, в два шага. Кнопка сначала показывает подтверждение, и лишь второе нажатие запускает удаление. Скрипт перед этим заново проверяет условия, потому что за время между нажатиями состояние могло измениться.

| Кнопка | Что должно быть верно | Что удаляется |
|---|---|---|
| **Discard local work** | запуск в `needs_attention` после отмены, владельца нет, HEAD равен `base_sha`, удалённой ветки нет | копия вместе с несохранёнными файлами (`--force`) и локальная ветка |
| **Close draft PR & discard** | копия чистая, локальный и удалённый HEAD совпадают, ровно один PR с этим коммитом, и он черновик | PR закрывается, удалённая ветка удаляется (`git push --no-verify`), затем копия и локальная ветка |

Удаление удалённой ветки идёт с `--no-verify`, чтобы хук `pre-push` проекта не оставил очистку недоделанной. Если хоть одно условие не выполнено (PR не черновик, PR слит, коммиты только локальные, коммиты не совпадают), скрипт возвращает `preserved` со списком причин и ничего не удаляет. В обоих случаях запуск после удаления переходит в `cancelled`.

Последний шаг — карточка. Когда запуск `cancelled` и ресурсы освобождены, контроллер переносит карточку в Backlog и записывает это в историю, чтобы не повторять.

::::example TT-42: от Done до удалённой копии
Данные придуманы. Запуск `r_3f9a1c7e5b2d4a8c6e01`, TailorTales; в этой копии Codex закончил и стоит на коммите `e77b3d0`.
:::steps
- **Ты** — 11:40 сливаешь PR #57 в GitHub и переносишь карточку в Done.
- **Опрос доски** — 11:41 записывает переход. Запуск становится `stopping`, `stop_reason=completed`. Карточка показывает «Stopping».
- **Контроллер** — 11:41 в том же цикле видит, что tmux-сессии нет (её закрыл `park`) и превью нет, и запускает очистку. Копия чистая, `git fetch` привозит новый `main`, `e77b3d0` оказывается предком `origin/main`.
- **Скрипт очистки** — удаляет `…/TT-42_add-dark-mode-toggle/TailorTales` и ветку `TT-42_add-dark-mode-toggle`, запись `merged_worktree_release_completed`.
- **Kurami** — запуск `archived`, ресурс `released`, карточка «Completed».
:::
::::

Если бы ты отменил задачу в 11:00, когда PR #57 ещё не был слит, картина была бы другой. Копия чистая, но ветка ушла на два коммита дальше `base_sha`. Скрипт отказался бы удалять и оставил карточку «Cancelled — published work preserved» с кнопкой **Close draft PR & discard**.

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Ты перенёс карточку в Done, а PR не слит (закрыт без слияния или брошен) | запуск переходит в `needs_attention` (`completion_waiting_for_merge`), работа сохраняется, слияние проверяется каждую минуту | слей PR — запуск завершится сам; или нажми **Cancel run** |
| Узнать о слиянии не вышло (ошибка `gh`, нет сети) | считает слияние недоказанным и ждёт | ждёшь или проверяешь GitHub |
| В копии несохранённые файлы при завершении | очистка отказывает; запуск в `needs_attention` | сохраняешь или выбрасываешь правки |
| Отмена: несохранённые файлы или новые коммиты | `needs_attention`, «Cancelled — … preserved» | Discard local work или Close draft PR & discard |
| Коммиты есть только локально, PR нет | ни одна кнопка удаления не подходит: `discard` требует HEAD на `base_sha` | разбираешься вручную |
| Удаление копии сорвалось на полпути | ресурс `partial`, запуск в `needs_attention` (`worktree_release_failed`) | смотришь причину |
| PR не черновик, уже слит или неоднозначен | `preserved` со списком причин, ничего не удалено | закрываешь или сливаешь PR сам |
| После отмены ты всё же слил PR | очистка повторяется каждую минуту; когда слияние доказано, копия удаляется и запуск становится `cancelled` | ничего |

:::guarantees
- Kurami не архивирует запуск и не удаляет ветку, пока не докажет слияние точного коммита.
- Kurami не удаляет несохранённые файлы при завершении: `git worktree remove` идёт без `--force`.
- Отменённый запуск не становится `archived`.
- Kurami не удаляет сохранённую или опубликованную работу без твоего подтверждения в два шага; закрывается только один черновой PR с точным совпадением коммитов.
- Контроллер не сливает PR автоматически. Projects выполняет слияние только после твоего подтверждения; переход карточки в Done остаётся за GitHub или тобой.
:::
