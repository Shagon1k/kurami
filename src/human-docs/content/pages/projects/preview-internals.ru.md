Превью — это временное приложение, собранное из рабочей копии запуска, которое Kurami публикует по одному из шести постоянных адресов. Слотами управляет менеджер, сборкой — адаптер, адресами — отдельная программа маршрутов, а истина о них лежит в двух таблицах SQLite.

:::glance
- Что делает: собирает точный коммит PR и открывает его по адресу `preview-N.shagon1k.win`
- Кто запускает: только ты, кнопкой Start preview; контроллер выполняет шаги
- Ритм: один шаг за минутный цикл — выдать слот, затем собрать
- Состояние: `preview_slots` (шесть слотов) и `preview_leases` (аренды слотов)
- Где работает: Docker без root-прав или статическая папка, перед ними Caddy на loopback
- Видно тебе: этап на карточке, событие Preview is ready, срок и отметка проверки
:::

## Пул из шести слотов

Слот — это заранее заведённый адрес и набор портов, которые Kurami арендует запуску. Шесть слотов лежат в таблице `preview_slots`: слот N получает адрес `preview-N.shagon1k.win`, адрес для файлов `assets-preview-N.shagon1k.win` и шесть портов на loopback. Адреса фиксированы, потому что маршруты туннеля и адреса возврата Google OAuth настраиваются на них заранее.

| Роль порта | Формула | Слот 3 |
|---|---|---|
| Frontend | 4310N | 43103 |
| Backend | 4320N | 43203 |
| PostgreSQL | 4540N | 45403 |
| Redis | 4630N | 46303 |
| MinIO API | 4910N | 49103 |
| MinIO console | 4920N | 49203 |

Адаптер Compose записывает выделенные порты frontend и backend в `runtime.env` как `PREVIEW_FRONTEND_PORT` и `PREVIEW_BACKEND_PORT`. Для существующих Compose-файлов он сохраняет `FRONTEND_PORT` и `BACKEND_PORT`. Обе пары обозначают те же порты слота; порты внутри контейнеров и привязки к loopback по-прежнему задаёт Compose-файл репозитория.

Слот занимает *аренда* — строка `preview_leases`, которая связывает слот, запуск и состояние. Частичные уникальные индексы гарантируют одну активную аренду на слот, одну на запуск и одну на имя Compose-проекта. Двойная выдача поэтому невозможна даже при гонке двух процессов. Одновременно активны не больше шести аренд (`max_previews_global`), а собираются не больше двух (`max_preview_builds_global`). Как это выглядит для тебя — в [Превью](@previews).

## Два адаптера

Адаптер — это код, который знает, как превратить рабочую копию в работающий адрес. Проект выбирает его в `projects.yaml`, а после выдачи слота Kurami запоминает выбор в аренде, чтобы позднейшая правка конфигурации не заставила один адаптер убирать чужие ресурсы.

| | Compose | Static |
|---|---|---|
| Кому подходит | приложение со стеком: база, MinIO, API | уже собранный сайт |
| Что делает | `docker compose up --build -d` в проекте `kurami-pvN-…` | копирует папку `dist` в неизменяемый снимок |
| Что проверяет | адреса health у frontend, backend и MinIO, до 180 с | `index.html` через Caddy, до 30 с |
| Секреты | из файла секретов проекта плюс случайные на запуск | нет |
| Ограничения | 4 ГиБ RAM, 20 ГиБ диска, два сборщика | не больше файлов и байт, чем задано (5000 и 256 МиБ по умолчанию) |

Static не запускает сборку и не выполняет чужой код. Он отвергает скрытые файлы, символические ссылки, специальные файлы и выход за папку, а хеш снимка сверяет с исходником: если файлы менялись во время копирования, сборка падает.

## Условия сборки

Сборка стартует, только когда проходят все проверки, и каждая защищает от конкретной беды. Контроллер выполняет их по порядку.

1. Запуск живой (`live`) и в состоянии `running`, `remote_owned` или `parked_review`. Иначе превью строилось бы для запуска, который уже умирает.
2. У запуска есть точный SHA из снимка CI (40–64 шестнадцатеричных символа). Без него нечего проверять.
3. Рабочая копия лежит внутри корня проекта, путь канонический, `HEAD` равен этому SHA, `git status` пуст, включая неотслеживаемые файлы. Так превью показывает ровно тот коммит, который увидит ревьюер.
4. Docker работает без root-прав, а свободно не меньше 4096 МиБ памяти и 20 ГиБ диска.
5. Все шесть портов слота свободны.
6. Идёт меньше двух сборок: аренда переходит в `provisioning`.

Если проверка падает до шага 6, аренда остаётся в `leased`; падение после шага 6 переводит её в `failed`. Ошибка шага запуска завершает запрос `preview_start` как `failed`: контроллер не запускает его снова каждую минуту. Аренда сохраняет владение слотом до штатного снятия превью.

**Stop preview** может заменить ещё не исполняемый `pending preview_start`, даже если слот уже выдан. В одной транзакции старый запрос становится `rejected` с причиной `preview_start_superseded_by_stop` и ссылкой на новый запрос снятия. Повтор Stop возвращает тот же ожидающий запрос. Контроллер снимает превью обычным `down`; запуск, PR, ветка и рабочая копия сохраняются.

Перед выдачей слота или запуском контроллер атомарно переводит запрос в `processing`. Stop не может заменить такой запрос: владелец получает отказ, пока текущий шаг не закончится. Уже построенный план отменённого запуска тоже не выполняется. При аварийном завершении контроллера запрос в `processing` остаётся защищённым; автоматический сброс без доказательства завершения внешнего шага не предусмотрен. Принятый Stop ещё не доказывает очистку: завершение подтверждают выполненный запрос и освобождённая аренда.

## Состояния аренды

Аренда проходит короткую линейную жизнь, и любой сбой приводит в `failed`, а не в тупик без владельца.

```diagram
kind: graph
title: Состояния аренды
desc: Аренда начинается в leased, при сборке переходит в provisioning, после проверок здоровья становится running. При снятии она идёт через releasing в released. Любая ошибка сборки или очистки переводит её в failed, откуда выход только через снятие превью.
direction: right
node leased "leased" "слот зарезервирован" state at 0,0
node provisioning "provisioning" "идёт сборка" state at 1,0
node running "running" "адрес открыт, срок 24 ч" state at 2,0
node releasing "releasing" "маршрут снят" state at 2,1
node released "released" "слот свободен" end at 2,2
node failed "failed" "слот занят" fail at 1,2
edge leased -> provisioning "claim, не больше 2"
edge provisioning -> running "health OK"
edge running -> releasing "снятие или срок"
edge releasing -> released "контейнеров нет"
edge provisioning -> failed "ошибка" accent
edge releasing -> failed "остатки" accent
edge failed -> releasing "Remove preview" dashed
```

`leased` значит «слот твой, ничего не построено». `provisioning` значит «сборка идёт»; аренда заходит сюда, только если сборок меньше двух. В `running` адрес открыт, а в `expires_at` записан срок. `released` — единственное окончательное состояние: слот свободен, а строка остаётся как история. Слот в `failed` остаётся занятым, пока ты не нажмёшь **Remove preview**. Так Kurami не отдаёт известный адрес под недочищенные контейнеры.

## Маршрут Caddy

Маршрут включается последним и выключается первым. Отдельная программа — единственная, кто пишет файл `routes.caddy`. Она берёт аренды в состоянии `running`, для каждой рисует пару маршрутов: адрес приложения ведёт на порт frontend, адрес файлов — на порт MinIO, а статический снимок раздаётся `file_server`. Всё остальное получает ответ 404. Перед заменой файла Kurami проверяет новую конфигурацию командой `caddy validate`, подменяет файл атомарно и перезагружает Caddy. Если перезагрузка не удалась, прежний файл возвращается и перезагружается снова.

Порядок защищает от двух вещей. Адрес появляется только после того, как аренда стала `running`, то есть после здоровой сборки. При снятии аренда сначала переходит в `releasing`, маршрут убирается, и лишь затем контейнеры останавливаются: чужой запрос уже не попадёт в наполовину разобранное приложение. Caddy слушает только `127.0.0.1:9180`, а публичный доступ даёт внешний туннель.

## Срок жизни и продление

Срок отсчитывается от здоровой сборки и по умолчанию равен 24 часам (`preview_ttl_hours`; в [настройках](@settings) — от 6 до 72), время сборки в него не входит. За два часа до конца (`preview_expiry_warning_hours`) карточка показывает **Extend 24h**. Продление добавляет 24 часа к текущему сроку и записывается в `run_state_history`. Продлить до истечения срока можно, после него — нет. Когда срок вышел, контроллер первым же шагом планирует `preview_expire`: адаптер выполняет `down` с причиной `preview_ttl_expired`, даже если в очереди ждёт другой запрос.

## Точный коммит и статус Done

Превью считается доказательством только для того коммита, из которого оно собрано. Аренда хранит `verified_head_sha`. Когда ты нажимаешь **Mark reviewed**, Kurami записывает на аренде метку проверки, а в запуске отметку «политика выполнена» — только если у запуска включён `preview_required` и `verified_head_sha` равен текущему SHA из снимка CI.

Флаг `preview_required` запуск получает при допуске, если у задачи в этот момент стояла метка `preview-required`. Когда позже приходит Done, а свежей отметки нет, контроллер не завершает запуск. Он ставит `completion_requested_at` и показывает этап **Preview required**. Новый коммит в PR сразу обесценивает старую отметку: SHA не совпадают, карточка пишет «Outdated», и нужно пересобрать превью. Когда доказательство актуально, контроллер сам завершает запуск.

::::example PF-33: превью для PR #41
Запуск `r_9f3a0c17d2b4`, ветка `PF-33_watchlist-sharing`, PR #41, коммит `4be1d9c`. Данные придуманы.
:::steps
- **Ты** — в 10:05 нажимаешь **Start preview**. Плагин ставит запрос `preview_start`, карточка встаёт на Preview queued.
- **Контроллер** — в 10:06 выдаёт слот 1: `preview-1.shagon1k.win`, порты 43101…, Compose-проект `kurami-pv1-3a0c17d2b4`.
- **Контроллер** — в 10:07 проверяет `HEAD == 4be1d9c` и чистый `git status`, память, диск и порты и переводит аренду в `provisioning`.
- **Адаптер Compose** — пишет `runtime.env`, запускает `docker compose up --build -d`, ждёт health до 180 с и ставит `running`, срок до завтра 10:11, `verified_head_sha=4be1d9c`.
- **Программа маршрутов** — добавляет пару маршрутов слота 1 и перезагружает Caddy.
- **Discord** — в треде событие **Preview is ready** со ссылкой, карточка показывает «Not reviewed».
- **Ты** — в 10:20 нажимаешь **Mark reviewed**: метка записана, `preview_required` выполнен, так как SHA совпали.
- **Ты** — в 10:30 переносишь задачу в Done. Контроллер завершает запуск, `down` снимает маршрут, затем контейнеры, и аренда становится `released`.
:::

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Нет памяти, диска или портов, заняты все слоты или два сборщика | выдача слота может повторяться; ошибка шага запуска завершает Start и сохраняет выделенную аренду | снять превью, затем запросить новый запуск при доступной ёмкости |
| У PR нет SHA из CI, рабочая копия грязная или `HEAD` не совпал | запрос Start в `failed`; аренда остаётся `leased`, без автоматического повтора запуска | исправить доказательства коммита, снять превью и запросить новый запуск |
| Сборка или health упали | аренда `failed`, событие Preview failed, этап Needs attention | нажимаешь Remove preview, чинишь, запускаешь снова |
| Caddy не перезагрузился | прежние маршруты возвращены; если и это не вышло, ошибка обеих попыток | чинишь юнит Caddy |
| Срок вышел | `down` с причиной `preview_ttl_expired` | запускаешь заново или продлеваешь за два часа до конца |
| Остался каталог `state/previews/<run>` после снятия | ничего не удаляет сам | запускает `reconcile-orphan-runtime` вручную |
| Сборка Compose идёт долго, до 30 минут | она выполняется внутри шага контроллера, другие проекты в это время пропускают свой шаг | ждёшь |

:::guarantees
- Kurami не запускает превью сам: каждое начинается с твоей кнопки.
- Превью собирается только из чистой рабочей копии с `HEAD`, равным коммиту, проверенному CI.
- Маршрут снимается раньше контейнеров, а слот освобождается только после проверки, что контейнеров нет.
- Превью старого коммита не засчитывается: политика требует SHA текущего PR.
- Отметка Mark reviewed не одобряет слияние и не продлевает срок.
- Static не выполняет сборку и не принимает скрытые файлы, символические ссылки и выход за папку.
:::
