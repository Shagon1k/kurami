Kurami запускает исправления CI и ревью через app-server и сохраняет точные идентификаторы потока и хода в Run Store.

:::glance
- Протокол: исправления CI и ревью; AI-ревью сохраняет протокол только для чтения
- Триггер: контроллер запускает одну управляемую задачу в назначенной рабочей копии
- Исполнение: отдельный процесс app-server через stdio; tmux сопровождает процесс
- Состояние: задача, поток, ход, статус завершения и подтверждение остановки процесса
- Результат: завершённый ход можно припарковать; доказательства Git, PR и CI проверяются отдельно
- TUI: основные писатели, преемники, human-control и старые сессии сохраняют наблюдение завершения и кнопки Remote
:::

Основные автономные писатели и преемники продолжают запускаться через прежний TUI. Human-control и передача Remote сохраняют этот путь. Миграция не присваивает старым сессиям предполагаемые идентификаторы протокола.

## Рабочая копия и учётные данные

Для каждого допущенного запуска Kurami создаёт отдельную связанную рабочую копию (worktree) и ветку. Перед исполнением система проверяет корневой каталог, репозиторий, ветку и сохранённый базовый коммит. Скрипт запуска также проверяет принадлежность копии точному основному клону и наличие отдельного Git-каталога.

Worker использует `workspace-write`: писать разрешено в копию, её отдельный Git-каталог и общий Git-каталог. Доступ к сети сохраняется для инженерного процесса. Каталог исходников основного клона не добавляется к разрешённым для записи. Run Store и каталог промптов находятся вне доступных модели корней записи.

Скрипт запуска читает прежний токен писателя из `secrets/github.env`; права файла должны быть закрытыми. Файл промпта имеет права 600 и удаляется после чтения. Технический worker получает `GH_TOKEN` писателя; посторонние секреты и данные GitHub App ревьюера удаляются из окружения. Квитанции протокола не содержат токенов, промптов или команд. Структурированное AI-ревью сохраняет отдельный путь app-server только для чтения и точную схему ответа.

## Запуск и завершение задачи

Захват задачи сохраняет запуск, вид задачи, контекст и точное имя сопровождающей сессии. Уникальное ограничение активной задачи исключает двух писателей протокола одного запуска. Исправления CI и ревью также сохраняют исходный SHA и первоначальный снимок доказательств.

Worker записывает поток из ответа `thread/start`, затем ход из ответа `turn/start`. Ответы прямо связывают задачу с исполнением: задачи протокола не ищут самый новый разговор по рабочему каталогу. Поток технической задачи также записывается в попытку исправления CI или раунд ревью. Прежний основной поток остаётся в `previous_codex_thread_id`, пока существующая очистка не восстановит его.

Записать итоговый статус может только `turn/completed` для точного потока и хода. Статусы `completed`, `failed` и `interrupted` различаются. Первая итоговая квитанция сохраняется; повторные и противоречащие события не меняют её. События другого потока, старого хода или освобождённой задачи не имеют полномочий.

После завершения worker закрывает app-server и ждёт выхода процесса, затем записывает `stopped_at`. Контроллер паркует только завершённый ход без кода ошибки и с подтверждённой остановкой. Затем он убирает точное сопоставление сессии и записывает `parked_review`, владелец `none`. Текст терминала не управляет задачами протокола. Сессии TUI сохраняют проверку завершения, включая `Worked for 50s • 09:50` перед приглашением ввода. Признаки работы и запрос подтверждения блокируют завершение.

Завершённый ход не доказывает, что код закоммичен, отправлен, отревьюен или принят CI. Существующие проверки Git и PR проверяют доставку; CI проверяет точный итоговый SHA. Исправления ревью с недоставленными локальными изменениями сохраняются для внимания. Очистка технической задачи и закрытие замечаний сохраняют прежние проверки доказательств.

## Перезапуск, отмена и лимиты

После перезапуска контроллер читает сохранённую задачу и квитанцию завершения. Если worker исчез до подтверждения выхода процесса, контроллер читает из истории только точный сохранённый поток и ход. Он не возобновляет поток и не отправляет новый ход. Даже найденное завершение не подтверждает остановку: владение остаётся защищённым в `needs_attention`, пока неопределённое состояние процесса не разрешено.

Потерянный ответ `turn/start` означает неопределённый запуск. Kurami сохраняет эту неопределённость и останавливает отдельный процесс; запрос не повторяется. Поэтому перезапуск не создаёт второй ход незаметно.

Для задач протокола Cancel run и лимит времени запрашивают прерывание через `turn/interrupt`, затем ждут точного итогового события и выхода процесса. Отсутствие подтверждения остановки сохраняет владение писателя. Прежние лимиты по умолчанию: 240 минут для основного писателя и 90 минут для технических задач. Структурированная блокировка использования или оплаты имеет отдельный код; она не выдаётся за таймаут исполнения.

Неожиданные запросы подтверждения, разрешений, пользовательского ввода и неизвестные запросы сервера закрываются отказом. Подтверждения команд и файлов отклоняются, набор выданных разрешений пуст, неподдерживаемый запрос получает ошибку. Задача останавливается и требует внимания; расширение разрешений автоматически не принимается.

## Владение и Remote

Значения владельца сохраняются: `cli` — управляемый писатель Kurami, `none` — писателя нет, `remote` — ты в Codex Remote. Continue autonomously для Remote-запуска по-прежнему требует твоего явного подтверждения, что прежняя задача закончена. Система создаёт новую задачу, оставляя поток Remote историей.

Take control и Continue in Codex остаются среди кнопок. Основные автономные писатели, новые преемники и human-control сохраняют прежнюю передачу TUI и кнопки Remote. Старые сессии сохраняют завершение и лимиты. Для потока, созданного app-server, живая передача и последующий захват Remote возвращают `protocol_remote_handoff_unverified`. Наличие команд daemon и remote-control не подтверждает передачу отдельного stdio-worker подключённому мобильному хосту. Эту интеграцию нужно проверить до записи владения Remote для такого потока.

::::example Технический ход завершён, нового SHA ещё нет
Запуск `r_example42` создаёт задачу исправления CI `ct_example42`, поток `thread_example42` и ход `turn_example42`. Точное событие завершения сообщает `completed`; выход процесса подтверждён. Следующий цикл контроллера паркует запуск. PR сохраняет исходный SHA, поэтому успех CI не заявляется. Попытка исправления ждёт независимых доказательств.

## Сохранённый таймаут старого исправления CI

Отдельная команда восстановления охватывает старое исправление CI, которое завершилось строкой `Worked for 50s • 09:50`, но позже получило таймаут. Проверка требует разрешённый запуск и исходный запрос, идентификаторы задачи, хеш транскрипта, чистую связанную копию, неизменный SHA исходника и PR, свежий failed CI и отсутствие живого писателя или конфликтующего управления. Другие причины внимания получают отказ.

Оператор проверяет командой ниже, затем повторяет её с `--apply` после одобрения. Сначала приостанови параллельный запуск писателей. Восстановление паркует запуск и сохраняет оба потока и исходную попытку; блокировка оплаты остаётся как `legacy_ci_repair_completed_billing_block`. Автоматическая очистка остаётся заблокированной; команда не запускает писателя и не повторяет исправление. Прежняя явная очистка остаётся отдельным решением владельца перед передачей Remote.

```sh
node src/orchestrator/projects/sessions/recover-legacy-ci-timeout.ts --run-id r_367ac0dcb458a2f56692
```

Команда использует настроенный `KURAMI_HOME`. Точные доказательства и условия описаны в [операторской процедуре восстановления](repo:docs/codex-protocol-lifecycle.md).

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Задача упала или прервана | сохраняет копию и отдельный код ошибки протокола | проверяешь причину и решаешь, отменять ли запуск |
| Пришёл запрос разрешения | ничего не разрешает, останавливает worker, сообщает о проблеме | проверяешь запрошенную операцию |
| Блокировка оплаты или использования | записывает `external_billing_block` | решаешь вопрос лимита перед новой работой |
| Worker умер или потерян ответ старта | читает точную историю; повторно не запускает ход | разбираешь неопределённую границу процесса |
| Остановка процесса не подтверждена | сохраняет защиту владения писателя | проверяешь отдельный worker перед освобождением ресурсов |
| Take control выбран для потока протокола | сообщает явную блокировку интеграции Remote | сохраняешь копию и используешь описанную границу восстановления |
| У старой сессии TUI нет идентификатора протокола | сохраняет проверку завершения TUI, лимиты и передачу | используешь прежние кнопки |
| Ход завершился без доставленного PR или нового результата CI | ждёт независимых доказательств | проверяешь ветку и PR |

:::guarantees
- Одним запуском владеет не больше одного управляемого писателя.
- Kurami никогда не возобновляет Remote-поток и не отправляет ему ввод.
- Текст терминала не завершает задачу протокола; завершение старых сессий TUI сохраняется.
- Отсутствие идентификаторов, запрос разрешения и неподтверждённая остановка закрываются отказом.
- Отмена и ошибка сохраняют ветку, рабочую копию и идентификаторы протокола.
:::
