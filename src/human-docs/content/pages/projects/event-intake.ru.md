Опрос доски — это скрипт, который раз в минуту читает GitHub Project, сравнивает колонки карточек с прошлым снимком и записывает каждое изменение колонки как событие в очередь.

:::glance
- Что делает: читает доску, хранит снимок карточек, записывает переходы колонок как события
- Кто запускает: Hermes cron, раз в минуту, отдельно для каждого проекта
- Где работает: короткий скрипт в минутном цикле; файловая блокировка на проект
- Состояние: `project_items`, `project_events`, `project_poll_state` в Run Store
- Доступ к GitHub: только чтение, через GitHub CLI (`gh`) с токеном владельца
- Что видно: ничего напрямую; следствие — запуск в Discord или «Waiting for GitHub»
:::

## Первый опрос — исходный снимок

Опрос хранит снимок каждой карточки: колонку, задачу и время последней встречи. Пока для проекта нет строки в `project_poll_state`, опрос находится в режиме *baseline*: он записывает все карточки, но не создаёт ни одного события. Поэтому задача, которая уже стояла в In progress, когда ты подключил проект, ничего не запускает. Иначе подключение проекта разом стартовало бы неконтролируемые запуски Codex.

Со второго опроса режим другой. Опрос отмечает все карточки проекта как отсутствующие, затем проходит по полученным. Если карточка известна и колонка отличается от сохранённой, опрос записывает событие. Карточка, которой в снимке не было, события не даёт: новая задача, созданная сразу в In progress, не стартует. Начать можно только переносом. Что делает каждый перенос — в [Статусах доски](@board-statuses).

## Событие и его идентификатор

Идентификатор события вычисляется из содержимого, поэтому одно и то же изменение не попадёт в очередь дважды. Это sha256 от пяти значений: проект, id карточки, время, когда карточку видели в прошлый раз, прошлая колонка и новая колонка. Повторная вставка того же идентификатора игнорируется. Если процесс упал до фиксации транзакции, следующий опрос увидит то же изменение и вычислит тот же идентификатор.

В событие попадают данные, по которым потом решает допуск: открыта ли задача (issue), есть ли непустое описание и какие на ней метки. Допуск не перечитывает GitHub. Поэтому решение принимается по тому состоянию задачи, которое было в момент переноса.

## Одна транзакция на проект

Снимок, события и отметка здоровья пишутся в одной транзакции SQLite. Опрос не оставляет базу наполовину обновлённой: либо всё, либо ничего. После успеха в `project_poll_state` записываются время снимка, число карточек, длительность и остаток лимита GitHub. После сбоя туда записывается `last_attempt_state = failed` и текст ошибки.

Доску читает запрос GraphQL по сто карточек на страницу. Он читает колонку, а также для задачи — состояние, заголовок, адрес, описание, метки и репозиторий. Проекты принадлежат пользователю, а не организации: запрос идёт через `user(login: …)`.

## Минутный цикл и блокировки

Опрос — вторая стадия в `run-project-poller.sh`. Три проекта стартуют одновременно, и у каждого своя блокировка `project-poller-<проект>.lock`: если прошлый опрос ещё идёт, новый молча завершается. Опросы разных проектов идут параллельно. Допуск и контроллер стоят позже под общей блокировкой; об этом — в [Контроллере](@controller).

Если опрос нашёл переходы, он печатает их текст, а скрипт запускает обновление Projects Digest. Если опрос упал, скрипт пишет ошибку в журнал и продолжает цикл: существующие запуски должны обслуживаться, пока GitHub недоступен.

::::example Задача TT-42 переходит в In progress
:::steps
- **Kurami** — в 10:01:04 опрос проекта tailortales читает доску. Для проекта уже есть `project_poll_state`, значит режим poll.
- **Опрос** — у карточки `PVTI_lAHOABC123` колонка Backlog, а стала In progress. Он вычисляет `event_id = c482c789e9b7…` и пишет событие с описанием, метками и состоянием issue на этот момент.
- **Опрос** — обновляет `project_items.status` и `project_poll_state.last_captured_at`, фиксирует транзакцию и печатает `tailortales #42: Backlog → In progress`.
- **Допуск** — в той же минуте берёт событие из очереди и создаёт запуск `r_26d6bafe366257202f23`.
:::
::::

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| GitHub недоступен, токен просрочен или исчерпан лимит | Опрос завершается с ошибкой и записывает `last_attempt_state = failed`. Если снимок старше двух минут, новые рабочие копии и сессии Codex не стартуют, карточка показывает «Waiting for GitHub». Существующие запуски продолжают обслуживаться | Проверь токен `gh`; после удачного опроса всё продолжится само |
| Процесс опроса убит посреди записи | Транзакция откатывается. Следующий опрос находит тот же переход и записывает то же событие | Ничего |
| Два опроса одного проекта пересеклись | Второй видит блокировку и завершается без действий | Ничего |
| Карточку перенесли туда и обратно между двумя опросами | Kurami не видит промежуточных колонок: сравнивает только с прошлым снимком | Ничего |
| Карточка создана сразу в In progress | События нет; задача попадает в снимок | Перенеси её в Backlog и снова в In progress |

Свежесть снимка проверяет контроллер: только два шага — создание рабочей копии и запуск Codex — требуют опроса не старше двух минут. Остальное обслуживается и без свежего опроса.

:::guarantees
- Опрос только читает GitHub и ничего не меняет на доске.
- Первый опрос проекта ничего не запускает; запуск начинает только перенос известной карточки.
- Одно изменение колонки даёт не больше одного события, даже после сбоя и повторного опроса.
- Новые рабочие копии и сессии Codex стартуют только по снимку доски не старше двух минут.
:::
