Для каждого запуска Kurami ведёт в Discord три вида сообщений. В канале проекта появляется короткое **стартовое сообщение** «PF-33 · заголовок задачи». Под ним Kurami открывает **тред** `[PF-33] заголовок`. В треде лежит одна **карточка запуска** — самое нижнее сообщение бота, — а над ней короткие **события**: «Ready for review», «Preview is ready», «CI failed».

Карточка обновляется на месте. После каждого события Kurami публикует её заново ниже и удаляет прежнюю: история читается сверху вниз, актуальное состояние всегда внизу.

::shot{file="shot-run-ready-review.png" size="card" alt="Карточка запуска PF-33 на этапе Ready for review: CI упал, превью обязательно, кнопки Continue in Codex, Start preview, Attempt CI fix, AI Code Review и меню More actions." caption="До четырёх кнопок в строке, остальные — в меню More actions. Ссылки на задачу и PR идут отдельной строкой, а не кнопками."}

## Страница Projects

Открой Projects через меню «Приложения». В шапке выбери проект, найди задачу поиском
или отсортируй таблицу по задаче, статусу и состоянию Kurami. По умолчанию
интерфейс английский. На телефоне нижняя панель открывает «Проекты» и «Поиск»;
язык и тема расположены строками в «Настройках». Контурные иконки проектов — папки,
панда, лиса и карточка профиля; выбранная ссылка отмечена полоской слева. Поиск открывается вверху видимого экрана
и учитывает появление клавиатуры. На компьютере выбор проекта и языка остаётся в шапке.
На компьютере у строк таблицы увеличены отступы, а сама таблица прокручивается
внутри окна. На телефоне задача открывается
на весь экран: свайп вправо возвращает к списку, влево — к последней задаче.

Счётчики **в работе** и **ждут вас** слева — кнопки фильтрации. Первый показывает
задачи в работе и ожидающие твоего внимания, скрывая Backlog, Deferred и Done.
Второй оставляет задачи, требующие твоего решения. Каждый счётчик использует
ту же выборку, что и его фильтр. Повторный клик по включённой кнопке возвращает
все задачи; другая кнопка переключает вид. Выбор хранится в адресе страницы
и сохраняется при поиске, смене проекта и обновлении данных.

На телефоне кнопки фильтров показывают иконки и числа в одной строке с короткой
кнопкой синхронизации. Общий счётчик задач скрыт, чтобы панель занимала одну
строку. Полные названия кнопок остаются доступны скринридерам.
Рядом с синхронизацией остаётся индикатор: зелёный для свежих данных, янтарный
для задержки. Открой синхронизацию, чтобы увидеть время наблюдения каждого проекта.

В карточке можно изменить статус GitHub Project и нажать доступные действия
Kurami, включая AI Review и управление превью. Они используют общую с Discord
очередь. Синхронизация показывает свежесть каждого проекта; страница обновляется
каждые 30 секунд. Поля проверок показываются текстом, а статус задачи — бейджем.
Метка Suggested next берётся из того же рейтинга, что и Projects Digest.
Discord продолжает показывать уведомления и состояние запуска.
Если запуск агента и его этап не наблюдались, колонка Kurami показывает **Нет запуска**.
Это отдельно от статуса задачи в GitHub, в том числе Done.

### Завершить pull request

Внизу управляемой задачи **Отменить запуск** находится рядом с действием для PR.
Когда действие для PR недоступно, пояснение находится под кнопками;
**Отменить запуск** занимает всю строку, а не делит её с текстом.
Для draft кнопка **Готово к проверке** открывает подтверждение снятия draft.
Для открытого PR без draft кнопка **Смержить PR** открывает компактное меню способов:
Squash, Rebase или Merge-коммит. Выбери способ, затем подтверди его в том же попапе:
**Смержить через Squash**, **Смержить через Rebase** или **Создать merge-коммит**.
Сам выбор способа не мержит PR. Настройки репозитория и действующие правила ветки
ограничивают список; Squash идёт первым, когда доступен. Страница читает
GitHub при открытии задачи и обновляет эти данные вместе с карточкой, не задерживая таблицу.

Оба действия требуют задачи в работе или на ревью, свежих данных проекта и остановленного запуска без владельца.
Перед записью Kurami повторно проверяет PR, коммит, права и требования к слиянию.
Запрос слияния передаёт показанный SHA без обхода правил GitHub. Стековые PR,
ветки назначения кроме основной и очереди слияния остаются под управлением GitHub.

Принятый GitHub запрос слияния ещё не означает, что PR смержен. **Проверить** проверяет
тот же запрос через 30 секунд, не выполняя повторную запись. Пока результат
ожидается или не подтверждён, управление запуском и изменение статуса заблокированы.
Kurami оставляет статус Project прежним: настроенная автоматизация GitHub может
перенести задачу в Done после слияния. Обычный опрос затем увидит этот переход.
Последующая чистка описана в [Завершении и очистке](@release-cleanup).

Редактор статуса всегда виден. Ссылки на задачу, PR, ревью и Discord оформлены
кнопками с рамкой и собраны в сетку. CI, ревью и превью находятся
в одном блоке, а действия исправления — рядом со своей проверкой. У превью своя
ссылка и срок действия. Совпадающий коммит показан один раз; разные коммиты
остаются видны. Готовое ревью не означает отсутствие замечаний.

Одно действие занимает всю строку; два делят строку, включая открытие и удаление
превью. Продолжение работы, восстановление и очистка находятся ниже проверок
без отдельных заголовков. Пояснения выделены информационным цветом, а счётчики
ревью — моноширинным шрифтом.
Кнопки одной пары сохраняют равную высоту при переносе подписей. Подтверждение
удаления занимает всю область действий; его кнопки выровнены справа.

Исправление CI и ревью выделено синим, как и сохранение изменённого статуса.
Удаление превью — янтарным; подтверждение проверки превью — зелёным. Отмена запуска
и удаление работы остаются красными. Запуск превью или ревью, переходы по ссылкам
и снятие draft остаются нейтральными; недоступные действия — серыми.

При свайпе панель следует за пальцем; короткий жест возвращает её на место.
Последняя задача открывается из памяти страницы и затем обновляется. До свежего
ответа управляющие кнопки заблокированы. Вертикальная прокрутка и поля формы
не запускают переключение; подтверждение удаления также отключает свайпы.
Сохранённая позиция прокрутки восстанавливается до появления панели.

Результат запроса появляется в небольшом уведомлении справа снизу, а не рядом
с поиском. Успешные запросы исчезают автоматически. Ошибки и неподтверждённые
записи статуса остаются до закрытия или замены новым результатом. Обновление
таблицы сохраняет уведомление; на телефоне оно доступно внутри диалога задачи.
Поставленный в очередь запрос ещё не означает завершения действия: проверяй
текущее состояние карточки.

## Что показывает карточка

Карточка читается сверху вниз. Сначала идёт этап (**Ready for review**) и одна строка пояснения. Строка **Control** появляется, только когда важно, кто держит задачу: `AI Agent` — работает управляемый Codex, `You` — задача передана тебе. Ниже компактная таблица CI, AI review, Preview и Policy, за ней подробности по каждой проверке и строка ссылок: задача, PR, превью, Codex. В подвале — короткий id запуска и время обновления по местному времени.

Этап определяет, какие кнопки уместны. Названия этапов и кнопок даны так, как они выглядят в Discord.

| Этап | Что происходит | Что ты обычно делаешь |
|---|---|---|
| Preparing worktree, Starting Codex | Kurami готовит рабочую копию (worktree) и запускает Codex | ждёшь |
| Codex working | Codex пишет код | ждёшь или нажимаешь Take control |
| Ready for review | Codex закончил, PR открыт, сессия свободна | смотришь PR, при желании запускаешь проверки |
| Fixing CI, Review fix queued, Fixing review | Kurami запустил отдельную задачу Codex на исправление | ждёшь |
| Preview queued, Preview ready | превью строится или уже открыто | смотришь превью, нажимаешь Mark reviewed |
| Preview required | Done запрошен, но нужного превью ещё нет | запускаешь и подтверждаешь превью |
| Human control | задача у тебя, автоматика её отпустила | работаешь в Codex, затем Continue autonomously |
| Needs attention | автоматика остановилась и ждёт тебя | читаешь текст на карточке |
| Cancelled — local work preserved | запуск отменён, локальная работа сохранена | решаешь: сохранить или удалить |
| Completed | запуск завершён, ресурсы освобождены | ничего |

## Кнопки

Кнопка появляется, только когда действие допустимо в этом состоянии. Карточка показывает не больше четырёх кнопок в порядке ниже, остальные лежат в списке **More actions…**. Кнопки Take control, Continue in Codex и Continue autonomously описаны подробнее в [Ручном управлении](@human-control). Полную таблицу с id и именами запросов см. в [справочнике команд](@commands).

| Кнопка | Когда появляется | Что запускает |
|---|---|---|
| **Take control** | Codex работает в управляемой сессии | Kurami прерывает текущий ход Codex, дожидается паузы и отдаёт тебе тред |
| **Continue in Codex** | Codex закончил, задачей никто не владеет | Задача переходит к тебе, на карточке ссылка «Open in Codex» |
| **Continue autonomously** | задача у тебя | Ты подтверждаешь, что закончил. Kurami запускает новую задачу Codex в той же ветке |
| **Start preview** | проект поддерживает превью, превью ещё нет | Выдаётся слот и строится превью — см. [Превью](@previews) |
| **Remove preview**, **Extend 24h**, **Mark reviewed** | превью существует | Снять превью, продлить его, отметить проверенным |
| **Attempt CI fix** | CI упал или нет обязательной проверки, попыток меньше двух | Новая задача Codex исправляет именно этот коммит |
| **AI Code Review** | PR открыт, этот коммит ещё не ревьюили | Независимый ревьюер читает PR и публикует ревью в GitHub |
| **Fix Review** | в актуальном AI-ревью есть замечания | Новая задача Codex правит замечания и закрывает их треды |
| **Recover delivered fix** | исправление сохранено, но не закоммичено | Kurami перепроверяет сохранённую задачу и доводит её |
| **Cancel run** | отмена ещё не начата | Запуск останавливается, ресурсы освобождаются, задача возвращается в Backlog |

## Нажатие ставит запрос

Кнопка не выполняет действие сама. Плагин Discord проверяет, что нажал именно ты, записывает *запрос* в базу и сразу меняет карточку на «в очереди». Контроллер на ближайшей минуте перепроверяет условия и выполняет шаг. Поэтому ответ «Start preview queued» значит только «запрос принят». Результат появится на карточке: этап сменится, а в треде придёт событие.

Устаревшее или повторное нажатие безвредно. Если условие уже не выполняется, Kurami отвечает тебе одной строкой «Control rejected safely: …» или отклоняет запрос при обработке. Подробности — на странице [Discord: карточки и команды](@discord-control-plane).

## Команда /kurami status

Если карточка ушла далеко вверх или что-то выглядит устаревшим, напиши `/kurami status` внутри треда запуска. Kurami опубликует свежую карточку внизу и ответит ссылкой на неё. Вне треда запуска команда откажет, ничего не изменив. Команда доступна только тебе. Остальные команды `/kurami` — в [справочнике](@commands).

## Отмена и удаление сохранённой работы

**Cancel run** останавливает запуск и освобождает ветку, рабочую копию и превью. Если внутри осталась работа, которую нельзя терять молча, запуск переходит в «Cancelled — local work preserved» и ждёт тебя. Тогда карточка предлагает **Discard local work** для неопубликованной работы или **Close draft PR & discard**, если открыт черновой PR. Обе кнопки сначала открывают подтверждение только для тебя. Только после второго нажатия запрос попадает в очередь.
