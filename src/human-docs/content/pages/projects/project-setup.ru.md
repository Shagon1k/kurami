Проект подключается одной записью в `projects.yaml`, одним заданием опроса в Hermes и одной строкой в списке скрипта-опросчика. Перед первым запуском ты проверяешь запись командой готовности: она только читает и ничего не меняет.

## Что описывает запись проекта

Запись лежит в `$KURAMI_HOME/config/projects.yaml` (образец — `deploy/config/projects.yaml`). Все секции нужны, кроме `preview` и `triage`.

| Часть | Что задаёт | Зачем |
|---|---|---|
| Идентичность | `owner`, `project_number`, `repository`, `status_field` и пять названий колонок `statuses` | Какую доску читать и какие задачи допускать. Доска должна принадлежать пользователю, а не организации |
| Рабочее пространство | `canonical_repository`, `worktree_root`, `base_branch`, `branch_prefix` | Где Kurami создаёт рабочие копии (worktree). Основной клон — только источник; префикс даёт имена вида `TT-42_…` |
| Discord | `guild_id` и `channel_id` проекта | Куда приходят карточки и треды запусков |
| CI | `enabled`, `required_checks`, `missing_grace_minutes` | Какие проверки считаются для точного коммита PR |
| Triage | `priority_field`, `effort_field` | Что ранжирует и предлагает Projects Digest |
| Превью | `adapter` (`compose` или `static`), метка `required_label` и параметры адаптера | Есть ли кнопка Start preview и когда превью задерживает завершение |
| Человеческое управление | `human_control_label` | Какая метка отдаёт запуск тебе |

## Проверка готовности

Команда читает запись и выдаёт список проверок. Каждая — PASS, WARN или FAIL.

```
npm run readiness -- --project <ключ>          # только конфигурация
npm run readiness -- --project <ключ> --live   # плюс GitHub и локальные пути
```

| Уровень | Значение | Код выхода |
|---|---|---|
| PASS | Факт на месте и согласован | 0 |
| WARN | Проект работает, но нет необязательной возможности или живого подтверждения. Предупреждение остаётся видимым | 0 |
| FAIL | Проект допускать нельзя, пока запись не исправлена | не ноль |

Режим `--live` дополнительно проверяет, что репозиторий и доска читаются, базовая ветка существует, поле статуса и все пять колонок есть на доске, имена проверок CI встречаются на базовой ветке, а локальные пути и файл секретов превью существуют. Имя проверки, которого нет на базовой ветке, даёт WARN, а не FAIL: часть проверок бывает только в PR.

## Что ещё нужно сделать

Одной записи мало: опросчик знает проекты из собственного списка.

1. В `run-project-poller.sh` добавь ключ проекта в оператор `case`. Без этого скрипт завершится с кодом 64.
2. Создай скрипт-обёртку `kurami-<проект>-poller.sh` (образцы — в `integrations/hermes/scripts/`), которая вызывает `run-project-poller.sh <ключ>`.
3. Добавь в Hermes задание `no_agent` с расписанием `* * * * *` и этим скриптом.
4. Положи секреты превью в файл вне Git, если проекту нужен Compose-превью.

Новый планировщик не нужен: блокировка контроллера общая для всех проектов, а опрос у каждого проекта свой.

## Чек-лист до первого запуска

:::steps
- **Ты** — прогоняешь проверку без `--live`: нет ни одного FAIL.
- **Ты** — читаешь каждый WARN и либо исправляешь, либо принимаешь сознательно.
- **Ты** — прогоняешь `--live` на сервере: снова ни одного FAIL.
- **Kurami** — дважды опрашивает доску: первый опрос записывает исходный снимок, второй не находит изменений. Почему так — в [От доски до события](@event-intake). Почему так — в [От доски до события](@event-intake).
- **Ты** — берёшь одноразовую задачу и проводишь её через допуск, рабочую копию, Draft PR, проверки точного коммита и Human Review до отмены или слияния.
- **Ты** — проверяешь превью, если оно настроено, и что карточка и Digest появились в нужных каналах.
- **Ты** — убеждаешься, что после проверки не осталось запусков, рабочих копий, превью и веток.
:::

Общие лимиты вместимости, такие как WIP и число Codex, лежат отдельно — в [Настройках](@settings). Что проект получает после подключения — в [Статусах доски](@board-statuses).

:::guarantees
- Проверка готовности только читает: у неё нет режима записи.
- Проект с FAIL в проверке допускать нельзя.
- Проект не подключают правкой SQLite, копией старого запуска или чужими ветками, каналами и идентификаторами превью.
- Проект не подключают правкой SQLite, копией старого запуска или чужими ветками, каналами и идентификаторами превью.
- Первый опрос нового проекта — исходный снимок: лежавшие на доске задачи ничего не запускают.
:::
