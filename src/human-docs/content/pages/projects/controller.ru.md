Контроллер — это скрипт, который раз в минуту читает все запуски из Run Store и для каждого выбирает ровно один следующий шаг: создать рабочую копию, запустить Codex, освободить сессию, перенести карточку в Human Review, убрать ресурсы.

:::glance
- Что делает: планирует и выполняет следующий шаг каждого запуска и каждой команды владельца
- Кто запускает: `run-project-poller.sh`, раз в минуту, под общей блокировкой
- Где работает: короткий процесс; сами шаги — дочерние скрипты
- Состояние: только Run Store; в памяти между циклами ничего нет
- Лимит: по умолчанию один Codex или AI-ревью одновременно (настройка Concurrent LLM)
- Что видно: смена стадии карточки запуска в Discord
:::

## Цикл контроллера

Контроллер работает в фиксированном порядке, чтобы каждый шаг видел результат предыдущего. Сначала он пересчитывает служебные записи: попытки исправления CI, раунды исправления ревью, AI-ревью, разовые уведомления и карточки прогресса. Затем считает, сколько процессов LLM уже работает. После этого строит план: один шаг на запуск и один шаг на каждую команду владельца. Потом выполняет план по очереди и после каждого шага снова пересчитывает служебные записи. В конце ещё раз обновляет уведомления и карточки.

План строится один раз в начале. Поэтому рабочая копия и запуск Codex происходят в разные минуты: запуск становится `starting` уже после того, как план составлен. Это цена простоты: один цикл не строит цепочку шагов вслепую, а каждый шаг основан на свежем состоянии.

Контроллер изменяет что-либо только при `mode: live` в `orchestrator.yaml`. В режиме `dry_run` он отказывается от `--apply`, а без `--apply` просто печатает план — так можно посмотреть, что он сделает.

## Правила следующего шага

Следующий шаг выбирает набор правил: побеждает первое подходящее. Правила только читают одну строку сводного запроса, где уже собраны факты о запуске, CI, превью и ревью, и ничего не меняют. Вот они, сгруппированные по смыслу.

| Условие запуска | Шаг | Что происходит |
|---|---|---|
| Превью истекло | `preview_expire` | Превью удаляется |
| Владелец просмотрел превью точного коммита и Done уже запрошен | `preview_requirement_complete` | Запуск переходит к завершению |
| На паузе ревью, PR и CI известны, карточка ещё в In progress | `project_review` | Карточка переносится в Human Review |
| Раунд исправления ревью дошёл до `resolving` | `review_fix_resolve` | Ответ и закрытие тредов GitHub |
| Осталась техническая задача Codex | `repair_cleanup`, `review_fix_cleanup` | Основной тред возвращается |
| Отменён, ресурсы освобождены | `project_backlog` | Карточка переносится в Backlog |
| Есть намерение отмены | `cancel_cli`, `resume_stop` | Отмена становится действием |
| `admission_pending` и снимок доски свежий | `provision` | Создаются ветка и рабочая копия |
| `starting`, копия готова и снимок свежий | `start` | Запускается Codex в tmux |
| Идёт работа, треда Codex ещё нет | `sync` | Записывается id треда |
| Codex закончил ход, запуск автономный | `park` | Сессия закрывается, запуск на паузе ревью |
| Запуск с меткой `human-control`, тред известен | `handoff` | Запуск передаётся тебе |
| `stopping`, нет tmux и превью | `release` | Копия и ветка удаляются, если безопасно |

«Снимок свежий» значит: последний опрос удался и не старше двух минут. Только `provision` и `start` ждут этого: новые задачи нельзя начинать по устаревшей доске, а обслуживание существующих запусков не прекращается.

Завершённый ход контроллер узнаёт по тексту в терминале Codex; признаки описаны в [Рабочей копии и сессии Codex](@codex-sessions).

## Команды владельца

Кнопка в Discord ничего не выполняет сама: она ставит запрос в очередь. Контроллер берёт его в следующем цикле и превращает в шаг. Как запрос попадает в очередь — в [Discord: карточки и команды](@discord-control-plane), сами кнопки — в [Управлении из Discord](@owner-controls).

Проверки делаются дважды. Скрипт команды отказывает сразу и человеческой фразой, например «Takeover is unavailable after cancellation was requested». Контроллер проверяет ещё раз в момент выполнения и записывает причину отказа, например `run_not_takeover_eligible`. Команда Cancel run сильнее остальных: она переводит запуск в `stopping` и отклоняет все другие команды этого запуска.

## Дочерние скрипты и повторная проверка

Контроллер сам почти ничего не делает: он вызывает узкие скрипты. Каждый скрипт заново читает запуск в своей транзакции и отказывается, если состояние уже изменилось («Run changed before …»). Это и есть защита от гонок. Два пересекающихся цикла не создадут две рабочие копии: второй скрипт увидит, что запуск уже не `admission_pending`.

Перед запуском Codex контроллер сверяет число работающих Codex и AI-ревью с лимитом (`max_llm_running_global`). Если лимит занят, шаги `start`, `successor_start`, `repair_start`, `review_start` и `review_fix_start` откладываются до следующей минуты. Запуск ждёт в состоянии `starting` с готовой копией.

Если дочерний скрипт упал, шаг откладывается и повторяется в следующем цикле. Команда остаётся в очереди, кроме запусков ревью, исправлений и восстановления: их команды помечаются `failed`, потому что повтор мог бы перезапустить уже начатую работу.

Если автоматический шаг раз за разом падает для одного и того же запуска, повторы реже. Первые пять неудач повторяются каждую минуту, дальше пауза удваивается (2, 4, 8 … до 30 минут), а первый успех её сбрасывает. Если шаг не проходит уже три часа, Hub показывает задачу как **Контроллер застрял**: с названием шага и числом неудач. Отказ, который значит лишь «ход Codex ещё идёт», пишется как ожидание, а не как ошибка. Команды владельца паузу не получают. Каждая строка `controller-errors.log` содержит время и уровень.

Когда запуск отменён или архивирован, агент больше не владеет им, а ресурсы освобождены, следующий цикл контроллера удаляет ошибки, записанные до перехода в конечное состояние. Hub скрывает эти устранённые ошибки, не дожидаясь очистки журнала. Более поздние сбои завершающих действий, например возврата отменённой задачи в Backlog, остаются видимыми.

::::example Запуск TT-42 за один час
:::steps
- **Контроллер** — в 10:01 правило `provision` создаёт ветку и копию: `admission_pending` → `starting`.
- **Контроллер** — в 10:02 правило `start` запускает Codex в tmux `cx-tt-42-26d6ba`: `running`, владелец `cli`.
- **Контроллер** — в 10:03 шаг `sync` записывает id треда Codex.
- **Контроллер** — в 10:44 терминал показывает «Worked for 41m 12s», шаг `park` закрывает сессию: `parked_review`.
- **Контроллер** — в 10:45 `project_review` переносит карточку в Human Review.
- **Контроллер** — в 11:21, после твоего Done и слияния, `release` удаляет копию и ветку: `archived`.
:::

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Два запуска скрипта пересеклись | Блокировка пропускает один; второй пропускает допуск и контроллер | Ничего |
| Допуск или контроль времени упал | Скрипт завершается с кодом 1 — контроллер в эту минуту не работает ни для одного проекта | Посмотри журналы `project-event-consumer-errors.log`, `runtime-budget-errors.log` |
| Дочерний скрипт отказал («Run changed before …») | Шаг откладывается, в следующей минуте план строится заново | Ничего |
| Лимит Codex занят | Запуск ждёт в `starting`, шаг откладывается | Дождись или подними лимит в [настройках](@settings) |
| Сервер перезагрузили | Состояние цело в базе; tmux-сессий нет | Смотри карточку: ошибка сессии видна там |
| Контроллер запущен в `dry_run` | Отказывается менять что-либо | Переключи `mode: live` сознательно |
| Один и тот же автоматический шаг падает снова и снова | Повторяет с растущими паузами; через три часа Hub показывает **Контроллер застрял** | Открой карточку задачи и реши: подождать, отменить запуск или починить сессию вручную |

:::guarantees
- Контроллер выбирает не больше одного шага на запуск за цикл.
- Каждый шаг заново проверяет состояние в своей транзакции и отказывается, если оно изменилось.
- Запущено не больше Codex и AI-ревью, чем позволяет лимит `max_llm_running_global`.
- Новые рабочие копии и сессии Codex стартуют только по свежему снимку доски.
- Команда владельца выполняется через очередь и проверяется дважды; Cancel run сильнее остальных.
:::
