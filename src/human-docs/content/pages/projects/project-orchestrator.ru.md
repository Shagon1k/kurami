:::glance
- Что делает: превращает перенос задачи в In progress в запуск Codex в своей ветке и рабочей копии (worktree)
- Кто начинает: ты — движением карточки на доске GitHub Project
- Ритм: раз в минуту — опрос доски, допуск новых задач и один шаг для каждого запуска
- Состояние: SQLite-база Run Store, одна строка `runs` на каждую попытку сделать задачу
- Где видно: карточка запуска и тред в Discord, PR и CI в GitHub
- Решения за тобой: слияние PR, выкладка, удаление сохранённой работы
:::

Project Orchestrator работает как термостат. Доска GitHub Project — это *желаемое* состояние: какие задачи ты хочешь видеть в работе. Run Store — *фактическое*: что уже создано, запущено и проверено. Раз в минуту Kurami сравнивает одно с другим и делает ровно один безопасный шаг, чтобы приблизить факт к желаемому. Никакого фонового демона нет: каждый шаг — короткий скрипт, который читает состояние из SQLite, проверяет его заново и записывает результат.

Внутри Kurami пять частей, и у каждой одна работа. **Опрос доски** читает GitHub Project и замечает, что карточка сменила колонку. **Допуск** решает, может ли задача стать запуском прямо сейчас. **Run Store** хранит всё, что известно о каждом запуске. **Контроллер** выбирает для каждого запуска следующий шаг и выполняет его. **Discord** показывает тебе состояние и принимает твои команды — кнопки не выполняют действие сразу, а ставят его в очередь для контроллера.

## Путь одной задачи

::::example Задача TT-42 «Add dark mode toggle»
:::steps
- **Ты** — в 10:00 переносишь карточку из Backlog в In progress.
- **Опрос доски** — в 10:01 видит смену колонки и записывает событие в очередь.
- **Допуск** — задача открыта, у неё есть описание, лимиты и диск в порядке. Появляется запуск в состоянии `admission_pending`.
- **Контроллер** — создаёт ветку `TT-42_add-dark-mode-toggle` и рабочую копию, а на следующей минуте запускает Codex.
- **Codex** — сорок минут пишет код, пушит коммиты и открывает PR. Kurami следит за CI именно этого коммита.
- **Kurami** — видит, что Codex закончил ход, и освобождает сессию. При подтверждённых PR и head SHA запуск может стать готовым к ревью и перейти в Human Review.
- **Ты** — смотришь PR, при желании просишь AI-ревью или превью и сливаешь PR. Kurami проверяет точную поставку запуска, останавливает превью и освобождает чистую рабочую копию без владельца. Приёмка всей задачи и перенос в Done — отдельные решения.
:::
::::

Каждая строка этого пути — отдельная минута или больше. Это нормально: контроллер делает по одному шагу на запуск за цикл, и поэтому любой сбой посреди пути оставляет понятное состояние, с которого следующая минута продолжит.

Если основной Codex останавливается без PR для ревью и head SHA, карточка ждёт решения владельца. Локальная работа сохраняется; CI и ревью не показываются как доступные. В App есть именованная ссылка на сессию и раскрываемые подробности остановки; в Discord отчёт отделён от статуса. Открытие ссылки не передаёт управление: **Continue in Codex** остаётся отдельным действием. При новых остановках сохраняется ограниченный и очищенный отчёт точной сессии; у старых запусков сохранённого отчёта может не быть.

## Три идеи, на которых всё держится

:::compare
### Доска — намерение, база — факт
Ты управляешь переносом карточек, а не процессами. Kurami реагирует только на *переходы* между колонками: карточка, которая уже стояла в In progress при первом опросе, работу не запускает.
### Один шаг, заново проверенный
Каждый шаг перечитывает запуск из базы и отказывается, если состояние успело измениться. Поэтому два пересекающихся цикла или падение процесса ничего не ломают: следующая минута просто повторит.
### Доказательство — точный коммит
CI, ревью и превью относятся к конкретному SHA последнего коммита PR. Новый коммит — новые проверки. Ветка удаляется, только когда её коммит доказуемо попал в основную ветку.
:::

:::guarantees
- Автоматический контроллер не сливает PR и не выкладывает приложение. Слияние в Projects требует твоего отдельного подтверждения.
- Не создаёт два запуска для одной задачи: это запрещено уникальным индексом в базе.
- Не удаляет несохранённую или опубликованную работу без твоего явного подтверждения.
- Не повторяет отказ молча: отклонённая задача ждёт, пока ты перенесёшь её снова.
:::
