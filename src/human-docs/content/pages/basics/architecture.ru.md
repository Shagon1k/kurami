Kurami — это не одно приложение, а около двух десятков коротких скриптов и нескольких постоянных сервисов на одном VPS. Почти никакая бизнес-логика не живёт в памяти: каждое задание запускается, читает состояние из SQLite или файла, делает свою работу, записывает результат и завершается. Благодаря этому любой процесс можно перезапустить в любой момент, и следующий запуск продолжит с того же места.

:::glance
- Сервер: один VPS, все сервисы слушают только `127.0.0.1`
- Планировщик: Hermes (12 cron-заданий) и два systemd-таймера
- Постоянные сервисы: сайт Digest, сайт документации, Hub, Caddy для превью, сэмплер CPU
- Состояние: `$KURAMI_HOME/state` — SQLite-базы и JSON-файлы
- Доступ снаружи: Cloudflare Tunnel и Cloudflare Access, только для владельца
- Выкладка: вручную — обновить код в `$KURAMI_HOME/app` и перезапустить нужный сервис
:::

Сверху вниз: внешний мир, Hermes, процессы Kurami, состояние. Hermes — это готовая среда агентов: она держит единственное подключение к Discord, раз в минуту проверяет расписание и умеет запускать модель со скиллами и инструментами. Kurami добавляет всё остальное: скрипты заданий, правила, базы и сайты.

## Что работает на сервере

| Процесс | Как запущен | Что делает |
|---|---|---|
| `hermes-gateway` | systemd, перезапускается всегда | тикер cron, приём кнопок Discord через плагин Kurami, агентные сессии, MCP-серверы |
| Опросы проектов (×3) | Hermes cron, каждую минуту | цикл Project Orchestrator для каждого проекта |
| Работник docs proposals | Hermes cron, каждую минуту | превращает еженедельный черновик документации в PR и карточку |
| Здоровье сервера | Hermes cron, по настроенному интервалу (5–60 минут) | собирает цикл здоровья, затем обновляет карточку здоровья и шлёт тревоги |
| Daily | Hermes cron, агентное задание | утренний выпуск Digest |
| Projects Digest, бэкап, обслуживание, Investment Review, аудит документации, скорость сети | Hermes cron, по расписанию | см. [расписание](@scheduling) |
| `kurami-briefing` | systemd, постоянно | сайт Digest |
| `kurami-human-docs` | systemd, постоянно | эта документация |
| `kurami-hub` | systemd, постоянно | Hub — закрытая веб-панель: живое состояние и несколько действий владельца |
| `kurami-preview-ingress` | systemd, постоянно | Caddy: маршруты к превью проектов |
| `kurami-cpu-statistics` | systemd, постоянно | замер CPU раз в 15 секунд для карточки здоровья |
| Страховка Daily и часовой опрос Digest | systemd-таймеры | проверка утреннего выпуска и обновление живых блоков |

Полный список с точным временем — в справочнике [Задания и расписание](@jobs).

## Два способа что-то запустить

:::compare
### По расписанию
Hermes раз в минуту сверяет расписание в UTC и запускает скрипт задания. Скрипт берёт файловую блокировку: если предыдущий запуск ещё идёт, новый тихо завершается. Местное время и выходные дни проверяет уже код — например, Daily сам решает, что 09:00 по местному времени наступило.
### По твоей команде
Кнопка или команда `/kurami` в Discord попадает в плагин Kurami внутри Hermes. Плагин проверяет, что нажал именно ты, и вызывает короткую команду CLI. Та почти всегда только ставит запрос в очередь в базе, а выполняет его ближайший цикл задания.
:::

Такая схема означает, что между твоим нажатием и результатом обычно проходит до минуты. Взамен любое действие проходит те же проверки, что и автоматическое, и оставляет след в базе.

## Как задания сообщают о себе

Задание Hermes бывает двух видов. **Скриптовое** — это просто скрипт: если он ничего не напечатал, Hermes никуда ничего не отправляет. **Агентное** — это сессия модели с навыками, так работают только Daily и еженедельный аудит документации. Отметка Hermes «задание выполнено» значит лишь, что скрипт завершился без ошибки. Поэтому скрипты Kurami сами пишут в Discord через API и сами хранят доказательство результата: квитанцию уведомления Daily, время обновления карточки здоровья, манифест бэкапа.

## Доступ снаружи

Все сервисы слушают только локальный адрес `127.0.0.1`. Снаружи до них можно дойти одним путём: Cloudflare Tunnel, затем Cloudflare Access с проверкой, что это ты, затем локальный сервис. Своей авторизации у сайтов нет, её роль выполняет Access, а действия владельца в Hub дополнительно проверяют токен Access. Настройки Tunnel и Access лежат в панели Cloudflare, а не в репозитории.

## Как код попадает на сервер

Автоматической выкладки нет. GitHub Actions на каждый PR запускает проверки: типы, тесты документации и регрессию. Выкладка — это ручное обновление checkout в `$KURAMI_HOME/app`, после которого:

- Digest пересобирается в `dist/` командой `npm run briefing:build`, а сервис `kurami-briefing` перезапускается;
- остальные части запускаются прямо из TypeScript закреплённой версией Node, поэтому новый код начинает работать со следующего запуска задания, а постоянные сервисы нужно перезапустить;
- плагин Discord и скиллы Hermes синхронизируются скриптами `bin/sync-hermes-plugin.sh` и `bin/sync-hermes-skills.sh`, после чего перезапускается `hermes-gateway`.

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Упал `hermes-gateway` | systemd сразу перезапускает его; пропущенные задания в пределах допуска выполняются после возврата | если карточка здоровья давно не обновлялась — проверить `systemctl --user status hermes-gateway` |
| Скрипт задания упал | задание помечено ошибкой; тихие задания ничего не присылают, ошибки пишутся в `logs/*-errors.log` | заглянуть в журнал конкретного задания |
| Два запуска наложились | второй видит занятую блокировку и тихо выходит | ничего |
| Сервер перезагрузился | сервисы и таймеры поднимаются сами, состояние в SQLite на месте; сессии Codex в tmux теряются и видны как требующие внимания | решить судьбу затронутых запусков в Discord |

:::guarantees
- Сервисы слушают только локальный адрес; снаружи к ним ведёт только путь через Cloudflare Access.
- Секреты не попадают в Git, журналы и обычные бэкапы; единственное место, куда копируется их часть, — зашифрованный архив восстановления.
- Каждое действие по кнопке проходит те же проверки, что и автоматическое, и оставляет запись в базе.
- Выкладка нового кода — ручное действие; сама себя система не обновляет.
:::

:::code-map
- `deploy/systemd/` — постоянные сервисы и таймеры
- `integrations/hermes/scripts/` — скрипты заданий Hermes
- `integrations/hermes/plugins/kurami-discord-controls/` — плагин кнопок и команд Discord
- `src/core/kurami-home.ts` — где искать `$KURAMI_HOME`
- `run-project-poller.sh` — самый частый цикл: опрос проектов
- `.github/workflows/regression.yml` — проверки на каждый PR
:::
