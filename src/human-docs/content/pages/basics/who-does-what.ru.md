В Kurami у каждого участника своя роль и свои полномочия, и эти границы проведены в коде, а не в договорённостях. Модель не может слить PR, потому что в коде нет такой операции. Кнопка не может обойти проверки, потому что она лишь ставит запрос в ту же очередь, что и автоматика.

:::glance
- Решает: ты — через доску GitHub, кнопки в Discord и публикацию правок
- Запускает: Hermes — по расписанию и по твоим командам
- Проверяет и записывает: код Kurami — детерминированно, с записью в SQLite
- Пишет текст и код: агенты — Hermes-агент для выпуска Daily, Codex для задач проектов
- Хранит работу: GitHub — доски, ветки, PR, CI
- Показывает: Discord — карточки, треды, тревоги
:::

## Роли

| Участник | Что делает | Чего не делает |
|---|---|---|
| **Ты** | задаёшь намерение переносом карточек, сливаешь PR, нажимаешь кнопки, меняешь настройки | не управляешь процессами напрямую: всё идёт через очередь и проверки |
| **Hermes** | держит подключение к Discord, раз в минуту сверяет расписание, запускает скрипты и агентные сессии, даёт агентам инструменты MCP | не знает правил Kurami и не хранит её состояние |
| **Код Kurami** | опрашивает источники, допускает работу, ведёт состояния, публикует, уведомляет, делает бэкапы | не принимает решений, отданных тебе: слияние, выкладка, удаление сохранённой работы |
| **Hermes-агент** | пишет редакционный черновик утреннего выпуска; раз в неделю готовит правки документации | не публикует сам: результат проверяет код, а правки документации — ты |
| **Codex** | пишет код задачи в своей ветке и рабочей копии, открывает PR, по кнопке чинит CI или замечания ревью | не выходит за рабочую копию, не сливает PR и не трогает доску |
| **GitHub** | хранит доски, код, PR и результаты CI; на ревью отвечает отдельный бот `kurami-ai` | — |
| **Discord** | показывает карточки запусков, выпуска, здоровья и принимает кнопки | не выполняет действий сам: кнопка лишь создаёт запрос |

## Одна задача глазами всех участников

```diagram
kind: sequence
title: Путь задачи между участниками
desc: Ты переносишь задачу на доске. Kurami замечает переход, допускает задачу и запускает Codex. Codex пушит код и открывает PR, Kurami читает CI точного коммита и сообщает в Discord, что всё готово. Слияние делаешь ты.
actor you "Ты" owner
actor gh "GitHub" external
actor kurami "Kurami"
actor codex "Codex"
actor discord "Discord" external
msg you -> gh "задача → In progress"
msg kurami -> gh "опрос доски"
self kurami "допуск: лимиты, диск, описание"
msg kurami -> codex "ветка, рабочая копия, промпт"
msg kurami -> discord "карточка «Codex работает»"
phase "работа"
msg codex -> gh "коммиты и PR"
msg kurami -> gh "CI точного коммита"
msg kurami -> gh "карточка → Human Review"
msg kurami -> discord "«Готово к ревью»" accent
phase "решение"
msg you -> gh "ревью и слияние"
msg you -> gh "задача → Done"
self kurami "проверка слияния, удаление ветки"
```

Обрати внимание, что Kurami и Codex почти не разговаривают напрямую. Kurami даёт Codex рабочую копию и промпт, а дальше читает результат там, где он лежит: коммиты и PR в GitHub, текст сессии в tmux. Поэтому Kurami может проверить каждое утверждение агента, а не верить ему на слово.

## Кто что может изменить

| Что меняется | Кто может | Как защищено |
|---|---|---|
| Колонка задачи на доске | ты; Kurami — только в Human Review после работы Codex и в Backlog после отмены | запись статуса есть в одном модуле, и он вызывается только контроллером |
| Код проекта | Codex в своей ветке | отдельная рабочая копия для каждого запуска; слияние только вручную |
| Выпуск Digest | код Digest по результату одного шага агента | проверки текста и покрытия до публикации; опубликованные новости больше не меняются |
| Настройки | ты, кнопкой в `/kurami settings` | лимиты Project Orchestrator — только когда он простаивает, каждое изменение — ревизия с откатом; интервал проверки здоровья — в любой момент |
| Документация | еженедельный агент готовит черновик, публикуешь ты | allowlist файлов, тесты, кнопка Publish |
| Почта | только снятие меток «входящие» и «непрочитанное» | отдельный контур коннектора с одним разрешённым инструментом |

:::guarantees
- Ни один агент не сливает PR, не выкладывает код и не удаляет сохранённую работу.
- Кнопка в Discord работает только для тебя и проходит те же проверки, что и автоматика.
- Результат агента всегда проверяет код до того, как он станет видимым.
- Hermes не хранит состояние Kurami: при потере Hermes состояние остаётся в базах Kurami.
:::

:::code-map
- `integrations/hermes/plugins/kurami-discord-controls/` — кнопки и команды: кто может нажимать
- `src/orchestrator/controls/run.ts` — постановка твоих запросов в очередь
- `src/orchestrator/projects/project-status.ts` — единственное место, где Kurami меняет колонку на доске
- `src/briefing/editorial-validation.ts` — проверка текста агента перед публикацией
- `deploy/config/connectors/` — контуры полномочий коннекторов
:::
