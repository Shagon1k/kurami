У каждого вопроса о Kurami есть одно место, где лежит правильный ответ, — *источник истины*. Карточки в Discord, страницы сайтов и сообщения только показывают копию этого ответа. Если карточка и база расходятся, права база: следующий цикл перерисует карточку по ней.

:::glance
- Намерение: доска GitHub Project — какие задачи ты хочешь видеть в работе
- Запуски: `state/orchestrator.db` — Run Store Project Orchestrator
- Выпуски: `state/briefing/briefing.db` и страницы в `state/briefing/pages/`
- Документация: `state/human-docs/proposals.db` и опубликованный релиз
- Здоровье: цикл в `state/system-health.db`; настройки: ревизии в Run Store и `state/health-settings.json`
- Витрина: Discord, сайты и Hub — перерисовываются из хранилищ; немногие действия Hub меняют состояние только через канонические инструменты
:::

## Какой вопрос — какое место

| Вопрос | Где правильный ответ | Что там смотреть |
|---|---|---|
| Какие задачи я хочу в работе? | доска GitHub Project | колонки задач |
| Идёт ли работа по задаче? | `orchestrator.db`, таблица `runs` | поле `state` и история `run_state_history` |
| Прошёл ли CI у этого PR? | `orchestrator.db`, `run_ci_snapshots` | результат для точного SHA последнего коммита |
| Вышел ли сегодняшний выпуск? | `briefing.db`, попытка выпуска | стадия попытки и квитанция уведомления |
| Здоров ли сервер? | цикл в `state/system-health.db`, его показывают карточка здоровья и Hub | время последней проверки и активные проблемы |
| Есть ли свежий бэкап? | `$KURAMI_HOME/backups/` | самая новая папка `backup-*` и её `manifest.json` |
| Какая документация опубликована? | `state/human-docs/release/build.json` | `docsSha` — коммит, из которого собран сайт |

Точные таблицы баз с описанием каждой — в справочнике [Хранилища данных](@data-stores).

## Discord — витрина, а не источник

Каждая карточка в Discord собирается из базы. Контроллер Project Orchestrator раз в минуту сравнивает, что должно быть на карточке запуска, с тем, что там уже есть, и правит её только при изменении. Карточка здоровья переписывается при каждой проверке. Если сообщение удалить, следующий цикл создаст новое и запомнит его идентификатор. Поэтому карточке можно доверять как индикатору, но решения о состоянии принимаются по базе.

## Как читать статусы

Статус в Kurami всегда относится к одному результату, а не ко всей системе. Сбой одного блока выпуска не означает, что сломан весь Digest.

| Слово | Что значит |
|---|---|
| **Актуально** | последнее принятое значение для указанного времени и источника |
| **Устарело** | свежая проверка не удалась или просрочена, показано последнее достоверное значение |
| **Частично** | полезные части прошли проверку, а пробелы показаны явно |
| **Сбой** | новый результат не принят; прежний успешный результат может оставаться на месте |
| **Ждёт тебя** | следующий шаг нельзя сделать автоматически, нужно твоё решение |
| **Принято** | пройдены проверки именно этого продукта; это не разрешение на слияние или выкладку |

Отсутствующее значение Kurami показывает как «—», а не как ноль. Ноль — это измеренный ноль, прочерк — «не знаю».

## «Задание выполнено» — ещё не результат

Hermes отмечает задание успешным, когда его скрипт завершился без ошибки. Это не значит, что работа сделана: скрипт мог честно выйти, увидев, что делать нечего или что ещё рано. Поэтому у каждого процесса своё доказательство результата — квитанция уведомления Daily, время обновления карточки здоровья, манифест бэкапа, `build.json` документации. Смотри на них, а не на отметку планировщика.

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Карточка в Discord устарела или удалена | следующий цикл перерисует или создаст её заново | ничего; если не обновляется долго — смотреть здоровье Hermes |
| Проверка источника не удалась | показывает последнее достоверное значение с пометкой «устарело» | ничего, пока не повторится; иначе — смотреть журнал |
| Потеряна база `orchestrator.db` | восстановление из последнего проверенного бэкапа | по порядку из [восстановления](@recovery) |
| Потеряна база `briefing.db` | восстановить из последнего бэкапа, в котором она есть; в старых копиях её нет, и история начнётся заново | проверить, что в свежем бэкапе есть `briefing.db` ([восстановление](@recovery)) |

:::guarantees
- У каждого вопроса одно место с правильным ответом; витрины перерисовываются из него.
- Неизвестное значение показано как «—» и никогда не выдаётся за ноль.
- Сбой одного результата не выдаёт себя за сбой всей системы и не стирает прошлый успешный результат.
:::
