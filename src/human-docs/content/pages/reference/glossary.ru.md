Слова, которые в документации значат что-то конкретное. Имена из кода даны `моноширинным шрифтом` и совпадают с кодом. Общие договорённости о словах — на странице [Как читать документацию](@how-to-read).

## Digest

:::terms
- **`content_digest`** — sha256 от `payload_json` и HTML выпуска; оптимистичная блокировка записи
- **`propagate` / `isolate`** — режимы сбоя: ошибка либо останавливает публикацию, либо убирает только свой блок
- **`SAVEPOINT` Weekly** — точка отката внутри транзакции публикации: сбой Weekly откатывает только её
- **add-on** — необязательный модуль Digest (Weekly, Cinema, Stocks…) со своими данными, страницей и правилом сбоя; его сбой не останавливает выпуск
- **Discovery** — до трёх проверенных акций США вне списка с заметным движением на повышенном объёме; только на `/stocks`
- **верхняя граница** — id самого нового сообщения канала при захвате; до него каналы помечаются прочитанными
- **выпуск** — страница Digest за одну дату (`daily:2026-10-01`) со строкой в `editions` и HTML-файлом; новости в ней заморожены, остальное живое
- **живые блоки** — почта, календарь, погода, Signals и полоса качества, которые опрос обновляет раз в час
- **замороженный тизер** — копия add-on в выпуске, снятая при публикации; опрос её не меняет
- **занятая дата** — строка в `stocks_refresh_days` / `stocks_discovery_days`, которую опрос вставляет перед работой: повтор в те же сутки невозможен
- **карточка** — единственное сообщение Discord на дату, которое правится на каждом этапе и становится карточкой выпуска
- **конверт** — запись `addons.<id>` в выпуске: версия, состояние, время снимка и данные
- **наблюдение** — компактная запись Weekly на дату: сюжеты, календарь, остаток почты, без текстов
- **охват** — сколько из семи дней недели наблюдалось по данному ряду Weekly, например 5/7
- **пачка** — замороженный список непрочитанных постов Telegram-каналов на момент захвата: сырой и нормализованный файлы
- **покрытие** — правило «каждый пост пачки принадлежит ровно одному сюжету или исключению»
- **полоса очков** — допустимый диапазон очков новости (не ниже границы минус 12), из которого модель выбирает
- **пометка каналов** — вызов `mark_read_through_batch` по сохранённому плану после проверки; единственное изменение Kurami в Telegram
- **попытка** — одна утренняя сборка выпуска: строка `briefing_run_attempts` с одиннадцатью состояниями и папкой файлов; на дату одна плановая попытка
- **принятый отчёт** — отчёт по портфелю, прошедший все проверки и записанный файлом по sha256 с указателем `latest-weekly.json`
- **профиль интересов** — веса тем и источников из твоих реакций 🔔/🔕; включается после 10 реакций и переставляет ленту в «Для меня»
- **реестр add-on** — статический массив из восьми модулей: порядок блоков, слоты и режим сбоя
- **скорректированная цена** — цена закрытия с поправкой на сплиты и дивиденды; по ней считаются изменения и графики
- **снимок** — последний удачный снимок add-on: одна строка на id, JSON данных и sha256
- **срез Cinema** — конверт Cinema за субботу; принимается, если данные есть в двух блоках (или во всех готовых)
- **сторож** — проверка systemd без модели: досылает уведомление, записывает сбой в сроки 09:50 и 10:50
- **сюжет** — новость выпуска: один или несколько склеенных постов с заголовком, пересказом и id `story-<16 знаков sha256>`
- **черновик** — `editorial-draft.json`: единственный результат агента — сюжеты, тексты, темы, оценки, исключения
:::

## Projects

:::terms
- **`deterministic-v2`** — формула выбора следующей задачи: уровень приоритета плюс малость оценки плюс возраст до 30 дней
- **`stop_reason`** — намерение остановки запуска: `completed` (Done) или `cancelled` (Backlog, Deferred, Cancel run)
- **AI-ревью** — независимый read-only проход Codex по diff PR, публикуемый ботом `kurami-ai[bot]` как одно нативное ревью `COMMENT`
- **Mark reviewed** — твоя отметка, что ты посмотрел превью именно этого коммита; не одобряет слияние и не продлевает срок
- **park** — шаг, который закрывает Codex после завершённого хода и переводит запуск в `parked_review` с владельцем `none`
- **Run Store** — единственная SQLite-база Project Orchestrator: события, запуски, ресурсы, история и очередь команд
- **tmux-сессия `cx-…`** — терминальная сессия, в которой живёт Codex CLI запуска; имя строится из префикса проекта, номера задачи и шести знаков id запуска
- **WIP** — число запусков, занимающих место; запуск на паузе ревью (`parked_review`) не считается
- **адаптер превью** — код, который превращает рабочую копию в работающий адрес: Compose (стек в Docker) или Static (готовая папка)
- **аренда превью** — строка `preview_leases`, связывающая слот, запуск и состояние (`leased`, `provisioning`, `running`, `releasing`, `released`, `failed`)
- **владелец копии** — кто сейчас пишет в копию: `none` — никто, `cli` — управляемая сессия Kurami, `remote` — приложение Codex
- **владелец сессии** — кто держит задачу Codex: `none`, `cli` (управляемая сессия) или `remote` (ты в приложении Codex)
- **доказательство слияния** — условие удаления после Done: HEAD копии — предок `origin/main` либо найден слитый PR ветки с тем же `headRefOid`
- **допуск** — проверка, которая решает, станет ли перенос карточки в In progress запуском; только записывает решение в базу
- **живой запуск** — запуск не в состоянии `rejected`, `cancelled` или `archived`; у карточки не бывает двух живых запусков
- **запрос** — строка `run_control_requests`, которую ставит нажатие кнопки; выполняет её контроллер
- **защита ресурсов** — осмотр каталогов, tmux-сессий и диска перед допуском; при расхождении блокирует допуск и открывает карантин, но ничего не удаляет
- **защищённая синхронизация** — запись принятых значений в GitHub Project, которая заново читает поле и не перезаписывает твоё значение
- **исходный снимок** — первый опрос проекта: карточки записываются, событий нет, поэтому лежавшие на доске задачи ничего не запускают
- **карантин ресурса** — запись о неучтённом каталоге или сессии: `observed`, через 30 минут `quarantined`, при исчезновении `resolved`
- **карточка запуска** — самое нижнее сообщение бота в треде запуска; правится на месте и показывает этап, проверки и допустимые кнопки
- **контроллер** — скрипт, который раз в минуту выбирает по одному следующему шагу для каждого запуска и команды владельца
- **намерение остановки** — `cancelled` или `completed`; отмена сильнее всего и не даёт оживить запуск
- **обязательные проверки** — имена проверок GitHub из `projects.yaml`, которые Kurami учитывает при оценке CI; остальные игнорируются
- **отпечаток карточки** — строка из десятков фактов; если она изменилась, Kurami перерисовывает карточку
- **пакет предложений** — замороженный список задач Backlog с пустыми Priority или Effort и предложения ИИ по ним, ждущие твоего решения
- **превью обязательно** — метка задачи, из-за которой запуск нельзя завершить без проверенного превью текущего коммита
- **преемник** — новый управляемый тред, который «Continue autonomously» запускает вместо старого треда, ушедшего к человеку
- **рабочая копия** — отдельный каталог с собственной веткой, в котором работает Codex одного запуска; основной клон репозитория рабочим каталогом не служит
- **раунд исправления замечаний** — одно нажатие Fix Review: снимок нерешённых потоков, задача Codex, ожидание CI и закрытие потоков
- **ревизия настроек** — неизменяемая запись набора лимитов с автором и контрольной суммой; создаётся командой `/kurami settings`
- **слот превью** — один из шести заранее заведённых адресов `preview-N.shagon1k.win` с набором портов, который Kurami арендует запуску
- **смена треда** — при технической задаче основной тред откладывается в `previous_codex_thread_id`, а после задачи возвращается
- **снимок CI** — единственная строка на запуск: PR, SHA его коммита и итог обязательных проверок (`pending`, `passed`, `failed`, `missing`, `unknown`)
- **снимок доски свежий** — последний опрос удался и не старше двух минут; только тогда стартуют новые рабочие копии и сессии Codex
- **событие в треде** — короткое разовое сообщение о переходе: Ready for review, Preview is ready, CI failed
- **сохранённая работа** — состояние `needs_attention` после отмены: копия и ветка оставлены, пока ты не подтвердишь удаление в два шага
- **техническая задача** — свежий Codex в той же копии для исправления CI или замечаний ревью; ограничен снимком доказательств
:::

## Платформа

:::terms
- **`$KURAMI_HOME`** — корневой каталог Kurami на сервере: код, состояние, секреты, копии и журналы
- **`composio-read`** — сессия только для чтения с семью инструментами; годится для фоновой работы
- **Cloudflare Access** — проверка личности перед доступом к локальным сервисам; своей авторизации у сайтов Kurami нет
- **Hermes** — готовая среда агентов на сервере: расписание, Discord, запуск модели, MCP
- **Hub** — закрытая страница с состоянием проектов, Git и расхода Codex; только чтение, слушает `127.0.0.1`
- **MCP-сервер** — внешний набор инструментов, к которому подключается Hermes; у него есть список разрешённых инструментов и уровень доверия
- **nonce** — одноразовая метка сообщения в Discord; сообщение с уже использованной меткой отбрасывается, поэтому повтор после сбоя не создаёт дубля
- **агентное задание** — задание Hermes, которое запускает сессию модели с промптом и скиллами (Daily, аудит документации)
- **белый список** — перечень путей, которые предложение вправе менять: страницы, журнал изменений, тест текстов и запись о покрытии
- **блокировка** — пустой файл, который скрипт берёт через `flock`; занятая блокировка означает тихий выход
- **выпуск документации** — сборка сайта из `main` с `revision: null`, которая подменяет каталог `release/`; прежний выпуск остаётся как `rollback-<sha>`
- **доставка** — куда Hermes отправляет вывод задания: `local` (никуда), `discord:<канал>` или `origin`
- **закреплённый Node** — одна фиксированная версия Node 24 в `runtime/node`, на которой запускается весь код Kurami
- **зашифрованный пакет** — архив со снимком, секретами и реестром cron, зашифрованный открытым ключом `age`; расшифровать его может только владелец закрытого ключа
- **карточка здоровья** — одно сообщение в канале здоровья, которое скрипт правит на месте и которое показывает текущее состояние сервера
- **отпечаток** — отсортированный список пар «ключ:серьёзность» активных проблем; его смена — повод для новой тревоги или восстановления
- **охранник интерфейса** — тест, который находит в коде продуктов ручные кнопки, литеральные цвета и переопределения библиотеки и сверяет их с замороженной базовой линией
- **предложение документации** — еженедельный набор правок страниц в отдельной ветке и PR, который публикуется только твоим кликом на карточке
- **проверка восстановления** — ручная расшифровка пакета на чистой машине со сверкой манифеста и `quick_check` базы
- **роль темы** — название назначения значения, а не самого значения: `--text-muted`, `--radius`; продукты стилизуются только ролями
- **серия проверок** — число проверок подряд, в которых проблема держится с одной и той же серьёзностью; тревога нужна только подтверждённой серии
- **скилл** — папка с инструкциями, которую Hermes подключает к агентной сессии
- **скриптовое задание** — задание Hermes, которое запускает только скрипт без модели; пустой вывод означает тишину
- **снимок** — согласованная копия базы Run Store и трёх файлов конфигурации с манифестом; секретов в нём нет
- **сторож** — таймер systemd, который проверяет, что утренний выпуск завершён, и правит карточку Daily
- **уровень Composio** — одна из трёх сессий доступа: `composio-read`, `composio-automation`, `composio`
:::
