Сборка Daily — это одна *попытка*: запись в базе, которая проходит одиннадцать состояний по порядку. Агент выполняет в этой цепочке ровно один шаг, а остальное делает код: читает источники, замораживает пачку постов, проверяет черновик и собирает выпуск. Попытка сохраняет каждое достигнутое состояние, поэтому после сбоя сборка продолжается с последнего. Как это выглядит для тебя — в [Утреннем выпуске](@daily).

:::glance
- Что делает: превращает всё непрочитанное за утро в принятый черновик и готовый к публикации выпуск за дату
- Запускает: задание Hermes `kurami-daily-briefing`, 09:00 по местному времени, окно восстановления — 10:00
- Где работает: агент вызывает команды runtime и инструменты Telegram MCP
- Состояние: строка в `briefing_run_attempts` и папка `$KURAMI_HOME/state/briefing/runs/<попытка>/`
- Итог для тебя: страница `/daily/<дата>` и карточка в Discord, которая доходит до «Выпуск опубликован»
:::

## Источники

Daily читает четыре источника, и каждый читается своим способом.

| Источник | Что берётся | Как читается |
|---|---|---|
| Новости | Непрочитанные посты 15 Telegram-каналов | Сервер Telegram MCP читает каналы через твой аккаунт |
| Почта | Непрочитанные письма из «Основных» Gmail | Composio, только чтение, до 20 страниц по 100 писем |
| Календарь | События дня из трёх календарей | Composio, только чтение |
| Погода | Текущая погода и прогноз на два дня | Open-Meteo, прямой HTTPS без ключей |

Новости берутся из Telegram, потому что «непрочитанное» — очередь, которая уже есть в самом Telegram: у каждого канала своя граница прочитанного. Собственного указателя Kurami не ведёт, поэтому каналы помечаются прочитанными только в конце, после публикации ([Публикация и восстановление](@daily-publication)). Сессия Composio для чтения ограничена семью инструментами, и через неё ничего нельзя изменить. Каждый вызов повторяется до трёх раз с таймаутом 12 секунд. Сбой почты или погоды не останавливает попытку, а делает выпуск «частичным».

## Заморозка пачки

Захват фиксирует, какие посты входят в сегодняшний выпуск, и больше эту границу не двигает. Для каждого канала он читает число непрочитанных и id самого нового сообщения — *верхнюю границу*. Затем собирает сообщения от последнего прочитанного до этой границы, но не больше 200 на канал. Посты, пришедшие позже, остаются непрочитанными для завтрашнего выпуска.

Каждый канал получает статус: `empty` (читать нечего), `ready` (собрано ровно столько, сколько непрочитано), `partial` (собрано меньше) или `failed` (диалог недоступен). Затем альбомы склеиваются: сообщения с общим идентификатором группы становятся одним постом, а картинки отделяются от прочих вложений. Проверка сверяет три списка id — заявленный, собранный и нормализованный. Захват *полный*, только если каждый канал `ready` без пропусков или `empty`. Только полный захват переводит попытку в `capture-validated`; при неполном сборка останавливается здесь.

Runtime завершает `collect-live` и фиксирует `live-collected` до начала сбора Telegram. Эти вызовы идут последовательно, а не параллельно. Коннектор проверяет этап до чтения снимка конфигурации, записи файлов и подключения к Telegram. Попытка в `created`, состоянии ошибки или конечном состоянии отклоняется с коротким машинным кодом.

Если исходная пачка сохранилась после прерванного перехода, разрешённое возобновление runtime позволяет использовать её повторно. Коннектор проверяет каталог попытки, дату, источник и настроенные каналы, затем нормализует и проверяет пачку без нового запроса Telegram. Исходные байты и утренняя граница остаются прежними. Некорректная сохранённая пачка останавливает сборку вместо повторного сбора. Готовая пара исходного и нормализованного файлов доступна на последующих активных этапах без перехода назад. Условия публикации и подтверждения прочтения не меняются.

## Единственный шаг агента

Агент читает пачку страницами по 50 постов и пишет `editorial-draft.json` — это вся его творческая работа. Для каждого сюжета он указывает, какие посты вошли, заголовок и краткий пересказ на русском, абзацы подробностей, темы с каноническими английскими id и четыре оценки: важность, срочность, общественный интерес, уверенность.

Посты, которые не стали сюжетом, он перечисляет в исключениях с одной из причин: `non-content`, `exact-duplicate`, `unsafe`, `unreadable`. Классы писем он тоже может переопределить.

Сначала агент пишет черновик без заметок и запускает пробный расчёт порядка (`rank-preview`): runtime прогоняет все проверки и печатает итоговый порядок. Дальше агент добавляет заметки Kurami — ровно `min(6, max(1, ceil(сюжетов / 5)))`, не больше одной на каждые пять сюжетов подряд. Так заметки опираются на реальные места в ленте, а не на порядок черновика.

## Проверка и сборка

Команда `compose` превращает черновик в единый выпуск, и это чистый код. Она проверяет, что заголовок и пересказ не копируют источник, что каждый пост принадлежит ровно одному сюжету или исключению, что темы допустимы ([Отбор и порядок новостей](@news-selection)). Затем присваивает сюжету id `story-` плюс первые 16 символов sha256 от списка его постов и применяет живые данные: почту, календарь, погоду. Порядок считает ранжирование `deterministic-v1`, а [Signals](@signals) вычисляются из принятых данных. Готовый выпуск проходит проверки ещё раз, и только после этого попытка получает состояние `editorialized`.

Выпуск хранится в одном формате: у каждого add-on свой конверт с состоянием, временем и данными ([Add-ons](@addons)). Новости лежат в конверте `news` вместе с границами захвата.

## Одиннадцать состояний

| Состояние | Кто переводит | Подпись в карточке |
|---|---|---|
| `created` | `start-attempt` | Подключаю источники |
| `live-collected` | `collect-live` | Почта, расписание и погода собраны |
| `telegram-captured` | Telegram MCP после записи пачки | Telegram-пачка получена |
| `capture-validated` | `validate-telegram-batch`, только при полном захвате | Проверяю и объединяю материалы |
| `editorialized` | `compose` | Сюжеты подготовлены |
| `prepared` | `render-preview` | Собираю изображения |
| `media-ready` | `import-media` или `media-ready` | Изображения готовы |
| `commit-planned` | `telegram-commit-plan` | Завершаю Telegram-гигиену |
| `telegram-committed` | `finalize` | Публикую страницу |
| `published` | `finalize` | Выпуск опубликован |
| `notified` | `notify-release` или сторож | Выпуск опубликован |

Состояния идут строго по порядку: перескочить или вернуться назад нельзя, повтор текущего состояния ничего не меняет. Из любого состояния попытка может уйти в `failed`. Последние шесть состояний, от `prepared` до `notified`, проходит инструмент `finish_daily_briefing`: он описан в [Публикации и восстановлении](@daily-publication).

::::example Попытка daily-2026-10-01--scheduled
:::steps
- **Runtime** — создаёт попытку и папку `runs/daily-2026-10-01--scheduled/`. Runtime читает 37 писем, 5 событий и погоду.
- **Telegram MCP** — 11 из 15 каналов имеют непрочитанное. У канала `space-news` 9 постов, верхняя граница — сообщение 48211. Всего 212 постов, 58 из них с картинками.
- **Агент** — склеивает посты 48211 и 48208 в один сюжет. Runtime присваивает ему id `story-3fa2c19b7d40e5a1`.
- **Агент** — оставляет 6 постов в исключениях как `non-content`. Итог: 206 постов в 41 сюжете плюс 6 исключений — все 212 учтены.
- **Runtime** — 41 сюжет требует `min(6, ceil(41/5))` = 6 заметок. `compose` принимает черновик, попытка становится `editorialized`.
:::
Данные придуманы; имена файлов и правила взяты из кода.
::::

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Composio или Open-Meteo не ответили | Блок получает статус `failed` без выдуманных данных, выпуск помечается «частичным»; ближайший почасовой опрос заполнит её | Ничего |
| Канал недоступен или собрано меньше, чем непрочитано | Захват неполный, `capture-validated` не достигается, сборка останавливается; повтор в 10:00 использует ту же замороженную пачку | Смотришь красную карточку; повторный захват — решение оператора |
| Черновик не прошёл проверки | `rank-preview` и `compose` возвращают список нарушений; `compose` удаляет результат, попытка остаётся на `capture-validated` | Ничего: агент чинит черновик в том же окне |
| Агент завершился раньше времени | Сторож записывает `agent_returned_incomplete`, в 10:00 попытка продолжается | Ничего |
| Telegram MCP недоступен | Агент фиксирует сбой инфраструктуры, а не «успешный пустой запуск» | Чинишь подключение Telegram в Hermes |
| Захват запущен повторно | Возвращает уже сохранённую пачку, граница не двигается | Ничего |

:::guarantees
- Агент пишет только черновик; порядок, id, страницу и публикацию делает код.
- Каждый пост из пачки принадлежит ровно одному сюжету или одному исключению — иначе `compose` отказывает.
- Граница пачки замораживается один раз и переживает повторы и окно восстановления.
- Захват ничего не помечает прочитанным и не скачивает картинки.
- Композитор не принимает неполный захват и черновик, который копирует источник.
- Сбор данных идёт через сессию Composio только для чтения; агент не вызывает общие инструменты Composio.
:::
