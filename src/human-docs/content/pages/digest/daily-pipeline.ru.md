Сборка Daily — это одна *попытка*: запись в базе, которая проходит одиннадцать состояний по порядку, и в этой цепочке агент выполняет ровно один шаг. Остальное делает код: читает источники, замораживает пачку постов, проверяет черновик и собирает выпуск. Попытка сохраняет каждое достигнутое состояние, поэтому после сбоя сборка продолжается с последнего.

:::glance
- Что делает: превращает всё непрочитанное за утро в принятый черновик и готовый к публикации выпуск за дату
- Запускает: задание Hermes `kurami-daily-briefing`, 09:00 по местному времени, окно восстановления — 10:00
- Где работает: агент вызывает команды runtime (`cli.js`) и инструменты Telegram MCP
- Состояние: строка в `briefing_run_attempts` и папка `$KURAMI_HOME/state/briefing/runs/<попытка>/`
- Итог для тебя: страница `/daily/<дата>` и карточка в Discord, которая ведёт до «Выпуск готов»
:::

## Источники

Daily читает четыре источника, и каждый читается своим способом.

| Источник | Что берётся | Как читается |
|---|---|---|
| Новости | Непрочитанные посты 15 Telegram-каналов | Сервер Telegram MCP читает каналы через твой аккаунт |
| Почта | Непрочитанные письма из «Основных» Gmail (`in:inbox is:unread category:primary`) | Composio, только чтение, до 20 страниц по 100 писем |
| Календарь | События дня из трёх календарей | Composio, только чтение |
| Погода | Текущая погода и прогноз на два дня | Open-Meteo, прямой HTTPS без ключей |

Новости берутся именно из Telegram, потому что «непрочитанное» — это очередь, которая уже есть в самом Telegram: у каждого канала своя граница прочитанного. Kurami не ведёт собственный указатель. Поэтому каналы помечаются прочитанными только в конце, после публикации ([Публикация и восстановление](@daily-publication)). Сессия Composio для чтения ограничена списком из семи инструментов, поэтому через неё нельзя ничего изменить. Каждый вызов повторяется до трёх раз с таймаутом 12 секунд; сбой почты или погоды не останавливает попытку, а делает выпуск «частичным».

## Заморозка пачки

Захват фиксирует, какие посты входят в сегодняшний выпуск, и больше эту границу не двигает. Для каждого канала инструмент `capture_daily_briefing_batch` читает число непрочитанных и id самого нового сообщения — *верхнюю границу*. Затем он собирает сообщения от последнего прочитанного до этой границы, но не больше 200 на канал. Посты, пришедшие позже границы, остаются непрочитанными для завтрашнего выпуска.

Каждый канал получает статус: `empty` (нечего читать), `ready` (собрано ровно столько, сколько непрочитано), `partial` (собрано меньше) или `failed` (диалог недоступен). Результат пишется в `telegram-raw.json`, затем альбомы склеиваются в `telegram-normalized.json`: сообщения с общим `grouped_id` становятся одним постом, картинки отделяются от прочих вложений. Наконец `validate-telegram-batch` сверяет три списка id — заявленный, собранный и нормализованный. Захват *полный*, только если каждый канал `ready` без пропусков или `empty`. Только полный захват переводит попытку в `capture-validated`; при неполном сборка останавливается здесь.

## Единственный шаг агента

Агент читает пачку и пишет `editorial-draft.json` — это вся его творческая работа. Пачку он получает страницами по 50 постов через `read_daily_briefing_batch_page`. Для каждого сюжета он указывает `sourceItemIds` (какие посты вошли), заголовок и краткий пересказ на русском, абзацы `details`, темы с каноническими английскими id и четыре оценки: важность, срочность, общественный интерес, уверенность. Посты, которые не стали сюжетом, он перечисляет в `exclusions` с одной из причин `non-content`, `exact-duplicate`, `unsafe`, `unreadable`. Дополнительно он может переопределить классы писем.

Сначала агент пишет черновик без заметок и запускает `rank-preview`: runtime прогоняет все проверки и печатает итоговый порядок. Дальше агент добавляет заметки Kurami — ровно `min(6, max(1, ceil(сюжетов / 5)))`, не больше одной на каждые пять сюжетов подряд. Так заметки опираются на реальные места в ленте, а не на порядок черновика.

## Проверка и сборка

Команда `compose` превращает черновик в единый выпуск, и это чистый код. Она проверяет, что заголовок и пересказ не копируют источник, что каждый пост принадлежит ровно одному сюжету или исключению, что темы допустимы ([Отбор и порядок новостей](@news-selection)). Затем она присваивает сюжету id `story-` плюс первые 16 символов sha256 от списка его постов и применяет живые данные: почту, календарь, погоду. Порядок считает ранжирование `deterministic-v1`, а Signals вычисляются из принятых данных. Готовый `payload.json` проходит проверки ещё раз, и только после этого попытка получает состояние `editorialized`.

Выпуск хранится в одном формате: `formatVersion: 3` с картой `addons`, где у каждого add-on свой конверт с состоянием, временем и данными. Новости лежат в конверте `news` вместе с границами захвата — `sourceBatches`.

## Одиннадцать состояний

| Состояние | Кто переводит | Подпись в карточке |
|---|---|---|
| `created` | `start-attempt` | Подключаю источники |
| `live-collected` | `collect-live` | Почта, расписание и погода собраны |
| `telegram-captured` | Telegram MCP после записи пачки | Telegram-пачка получена |
| `capture-validated` | `validate-telegram-batch`, только при полном захвате | Проверяю и объединяю материалы |
| `editorialized` | `compose` | Сюжеты подготовлены |
| `prepared` | `render-preview` | Собираю изображения |
| `media-ready` | `import-media` или `media-ready` | Изображения готовы |
| `commit-planned` | `telegram-commit-plan` | Завершаю Telegram-гигиену |
| `telegram-committed` | `finalize` | Публикую страницу |
| `published` | `finalize` | Выпуск готов |
| `notified` | `notify-release` или сторож | Выпуск готов |

Состояния идут строго по порядку: перескочить или вернуться назад нельзя, повтор текущего состояния ничего не меняет. Из любого состояния попытка может уйти в `failed`. Последние семь состояний проходит инструмент `finish_daily_briefing`, он описан в [Публикации и восстановлении](@daily-publication).

::::example Попытка daily-2026-10-01--scheduled
:::steps
- **Runtime** — создаёт попытку и папку `runs/daily-2026-10-01--scheduled/`. Runtime читает 37 писем, 5 событий и погоду в `live-snapshot.json`.
- **Telegram MCP** — 11 из 15 каналов имеют непрочитанное. У канала `space-news` 9 постов, верхняя граница — сообщение 48211. Всего 212 постов, 58 из них с картинками.
- **Агент** — склеивает посты 48211 и 48208 в один сюжет. Runtime присваивает ему id `story-3fa2c19b7d40e5a1`.
- **Агент** — оставляет 6 постов в исключениях как `non-content`. Итог: 206 постов в 41 сюжете плюс 6 исключений — все 212 учтены.
- **Runtime** — 41 сюжет требует `min(6, ceil(41/5))` = 6 заметок. `compose` принимает черновик, попытка становится `editorialized`.
:::
Данные придуманы; имена файлов и правила взяты из кода.
::::

## Что может пойти не так

| Ситуация | Что делает Kurami | Что делаешь ты |
|---|---|---|
| Composio или Open-Meteo не ответили | Секция получает статус `failed` без выдуманных данных, выпуск помечается «частичным»; ближайший почасовой опрос заполнит её | Ничего |
| Канал недоступен или собрано меньше, чем непрочитано | Захват неполный, `capture-validated` не достигается, сборка останавливается; повтор в 10:00 использует ту же замороженную пачку | Смотришь красную карточку; повторный захват — решение оператора |
| Черновик не прошёл проверки | `rank-preview` и `compose` возвращают список нарушений; `compose` удаляет результат, попытка остаётся на `capture-validated` | Ничего: агент чинит черновик в том же окне |
| Агент завершился раньше времени | Сторож записывает `agent_returned_incomplete`, в 10:00 попытка продолжается | Ничего |
| Telegram MCP недоступен | Агент фиксирует сбой инфраструктуры, а не «успешный пустой запуск» | Чинишь подключение Telegram в Hermes |
| Повторный вызов `capture_daily_briefing_batch` | Возвращает уже сохранённые файлы (`reused: true`), граница не двигается | Ничего |

:::guarantees
- Агент пишет только черновик; порядок, id, страницу и публикацию делает код.
- Каждый пост из пачки принадлежит ровно одному сюжету или одному исключению — иначе `compose` отказывает.
- Граница пачки замораживается один раз и переживает повторы и окно восстановления.
- Захват ничего не помечает прочитанным и не скачивает картинки.
- Композитор не принимает неполный захват и черновик, который копирует источник.
- Сбор данных идёт через сессию Composio только для чтения; агент не вызывает общие инструменты Composio.
:::
